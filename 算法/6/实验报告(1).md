## 二、实验背景

### 2.1 问题描述

在美国职业棒球大联盟（MLB）中，每支球队在一个赛季中要进行162场比赛。赛季结束后，胜场数最多的球队获得分区冠军。如果出现并列第一的情况，则通过附加赛决出冠军。

在赛季进行过程中，我们需要判断某支球队是否已经"被淘汰"——即无论剩余比赛结果如何，该球队都不可能获得冠军（或并列冠军）。

### 2.2 实际案例

本实验基于1996年NL West分区的真实数据：

| Team | Wins | Losses | To Play | Against (ATL/Phi/NY/Mon) |
|------|------|--------|---------|--------------------------|
| Atlanta | 83 | 71 | 8 | -/1/6/1 |
| Philly | 80 | 79 | 3 | 1/-/0/2 |
| NY | 78 | 78 | 6 | 6/0/-/0 |
| Montreal | 77 | 82 | 3 | 1/2/0/- |

**关键观察：**
- Atlanta已经83胜，最多可赢91场（83+8）
- Montreal最多只能赢80场（77+3），已被淘汰
- 但Philly虽然最多只能赢83场，情况却更复杂——需要考虑Atlanta输球时其他球队会赢球

## 三、流网络构造原理

### 3.1 问题建模

**核心思想：** 将棒球淘汰问题转化为最大流问题，通过判断最大流是否等于总剩余比赛场次来确定球队是否被淘汰。

**建模步骤：**

1. **确定被判断的球队 $s$**
2. **计算 $s$ 的最大可能胜场数：** $W_{max} = w_s + r_s$
3. **构建流网络 $G = (V, E)$**

### 3.2 流网络结构

**节点集合 $V$：**

| 节点类型 | 数量 | 说明 |
|----------|------|------|
| 源点 $s$ | 1 | 流量起点 |
| 比赛节点 | $k$ | 每对非 $s$ 球队之间的剩余比赛 |
| 球队节点 | $n-1$ | 除 $s$ 外的每支球队 |
| 汇点 $t$ | 1 | 流量终点 |

其中 $k = C(n-1, 2) = \frac{(n-1)(n-2)}{2}$

**边集合 $E$ 与容量 $c$：**

1. **源点 $\to$ 比赛节点：**
   - 对于每对球队 $(i, j)$ 的剩余比赛，添加边 $(s, \text{game}_{ij})$
   - 容量 $c(s, \text{game}_{ij}) = r_{ij}$（$i$ 和 $j$ 之间的剩余比赛场次）

2. **比赛节点 $\to$ 球队节点：**
   - 对于每个比赛节点 $\text{game}_{ij}$，添加边 $(\text{game}_{ij}, \text{team}_i)$ 和 $(\text{game}_{ij}, \text{team}_j)$
   - 容量 $c(\text{game}_{ij}, \text{team}_i) = \infty$（足够大的数）

3. **球队节点 $\to$ 汇点：**
   - 对于每支球队 $i$（$i \neq s$），添加边 $(\text{team}_i, t)$
   - 容量 $c(\text{team}_i, t) = W_{max} - w_i$（$s$ 的最大可能胜场数减去 $i$ 的当前胜场数）

## 四、最大流算法原理

### 4.1 最大流-最小割定理

**定理（Max-Flow Min-Cut Theorem）：** 在任意网络流 $G = (V, E)$ 中，从源点 $s$ 到汇点 $t$ 的最大流值 $f^*$ 等于最小割容量 $c^*(S, T)$。

$$f^* = c^*(S, T) = \min_{(S,T) \in \text{cuts}} \sum_{u \in S, v \in T} c(u, v)$$

**证明：**

**第一步：证明 $f \leq c(S, T)$**

对于任意 $s$-$t$ 割 $(S, T)$，其中 $s \in S, t \in T$：

$$f = \sum_{(u,v) \in E} f(u,v) = \sum_{u \in S, v \in T} f(u,v) - \sum_{u \in T, v \in S} f(u,v)$$

由于 $f(u,v) \leq c(u,v)$ 且 $f(u,v) \geq 0$：

$$f \leq \sum_{u \in S, v \in T} c(u,v) = c(S, T)$$

**第二步：证明存在割使得 $f = c(S, T)$**

设 $f$ 为最大流，定义：
- $S$：从 $s$ 通过正残留容量边可达的节点集合
- $T = V \setminus S$

则：
$$f = \sum_{u \in S, v \in T} f(u,v) - \sum_{u \in T, v \in S} f(u,v) = c(S, T)$$

因为从 $T$ 到 $S$ 的边流量为0（否则 $S$ 的定义不成立）。

### 4.2 Dinic算法

本实验采用Dinic算法求解最大流，该算法由Yefim Dinitz于1970年提出。

**算法核心思想：**

1. **构建分层图（Level Graph）：**
   - 使用BFS从源点开始，为每个节点分配层次（距离源点的最短距离）
   - 只保留满足 $level[v] = level[u] + 1$ 的边
   - 分层图保证了增广路径的长度单调递增

2. **DFS阻塞流（Blocking Flow）：**
   - 在分层图上进行DFS，找到所有增广路径
   - 使用"当前弧优化"（Current Arc Optimization）避免重复搜索
   - 一次DFS可以找到多条增广路径

3. **重复执行：**
   - 直到无法找到从源点到汇点的增广路径
   - 每次BFS后，至少存在一条增广路径

**算法伪代码：**

```
Algorithm Dinic(G, s, t):
    total_flow ← 0
    while BFS(G, s, t) finds a path from s to t:
        start ← array of zeros, size |V|
        while pushed ← DFS(s, t, ∞, start) > 0:
            total_flow ← total_flow + pushed
    return total_flow

Algorithm BFS(G, s, t):
    for each vertex v in V:
        level[v] ← -1
    level[s] ← 0
    Q ← empty queue
    enqueue(Q, s)
    while Q is not empty:
        u ← dequeue(Q)
        for each edge (u, v) with residual capacity > 0:
            if level[v] == -1:
                level[v] ← level[u] + 1
                enqueue(Q, v)
    return level[t] ≠ -1

Algorithm DFS(u, t, flow, start):
    if u == t:
        return flow
    while start[u] < degree(u):
        v ← next neighbor of u (using current arc)
        if level[v] == level[u] + 1 and residual(u, v) > 0:
            pushed ← DFS(v, t, min(flow, residual(u, v)), start)
            if pushed > 0:
                augment(u, v, pushed)
                return pushed
        start[u] ← start[u] + 1
    return 0
```

**流网络构造伪代码：**

```
Algorithm BuildFlowNetwork(teams, s):
    n ← number of teams
    W_max ← wins[s] + remaining[s]

    // 检查是否有球队已超过 W_max
    for each team i where i ≠ s:
        if wins[i] > W_max:
            return ELIMINATED

    source ← 0
    k ← number of remaining games between non-s teams
    game_nodes ← {1, 2, ..., k}
    team_nodes ← {k+1, k+2, ..., k+n-1}
    sink ← k + n

    // 添加源点到比赛节点的边
    for each pair (i, j) where i < j, i ≠ s, j ≠ s:
        if remaining_games[i][j] > 0:
            add_edge(source, game_node(i,j), remaining_games[i][j])

    // 添加比赛节点到球队节点的边
    for each game_node(i,j):
        add_edge(game_node(i,j), team_node(i), ∞)
        add_edge(game_node(i,j), team_node(j), ∞)

    // 添加球队节点到汇点的边
    for each team i where i ≠ s:
        cap ← W_max - wins[i]
        add_edge(team_node(i), sink, cap)

    // 求解最大流
    flow ← Dinic(G, source, sink)
    total_remaining ← Σ remaining_games[i][j] for all pairs

    // 判定淘汰
    return (flow < total_remaining) ? ELIMINATED : NOT_ELIMINATED
```

**时间复杂度：** $O(V^2 E)$

**空间复杂度：** $O(V + E)$

### 4.3 算法正确性证明

**定理：** Dinic算法能在有限步内终止并返回最大流。

**证明：**

1. **终止性：** 每次BFS后，分层图的深度严格递增，而深度最多为 $V-1$，因此算法必然终止。

2. **正确性：** 
   - 每次DFS找到的是分层图中的阻塞流
   - 阻塞流的性质保证了在当前分层图中没有增广路径
   - 当BFS无法到达汇点时，说明没有增广路径，此时流达到最大

## 五、为什么最大流能解决棒球淘汰问题

### 5.1 流量守恒的意义

在流网络中，每个比赛节点的入度（来自源点的流量）必须等于出度（流向两个球队的流量之和）。

**物理意义：**
- 每场比赛的胜利必须分配给参赛的两支球队之一
- 不能有"凭空产生"的胜利
- 保证了比赛结果的合理性

### 5.2 容量约束的意义

**球队节点到汇点的容量 $W_{max} - w_i$ 确保了：**

1. **上限约束：** 每支球队 $i$ 最多只能再赢 $W_{max} - w_i$ 场比赛
2. **淘汰判定：** 如果球队 $i$ 已经赢了超过这个数量，说明它已经超过 $s$ 的最大可能胜场数
3. **公平性：** 所有球队都受到相同的约束

### 5.3 判定淘汰的条件

**定理：** 球队 $s$ 被淘汰当且仅当最大流 $f^*$ 小于所有剩余比赛场次之和 $R$。

$$\text{Eliminated} \iff f^* < R$$

**证明：**

- **充分性（$f^* < R \Rightarrow$ 淘汰）：**
  - 如果最大流小于总剩余比赛场次，说明存在某些比赛无法分配胜利
  - 这意味着无论如何安排比赛结果，都会违反某些约束
  - 因此 $s$ 无法获得最多胜场

- **必要性（淘汰 $\Rightarrow f^* < R$）：**
  - 如果 $s$ 被淘汰，说明存在某个割 $(S, T)$ 使得 $s$ 无法获得最多胜场
  - 根据最大流-最小割定理，$f^* = c(S, T) < R$

### 5.4 等价条件

**推论：** 球队 $s$ 被淘汰当且仅当存在一个割 $(S, T)$ 使得 $s \in T$ 且：

$$\sum_{i \in S} w_i > W_{max} \cdot |S| - R_S$$

其中 $R_S$ 是集合 $S$ 内部球队之间的剩余比赛场次。

## 八、关键定理证明

### 8.1 最大流-最小割定理

**定理：** 对于任意网络流 $G = (V, E)$，从源点 $s$ 到汇点 $t$ 的最大流值等于最小割容量。

**证明：**

**第一步：证明 $f \leq c(S, T)$**

对于任意 $s$-$t$ 割 $(S, T)$，其中 $s \in S, t \in T$：

$$f = \sum_{(u,v) \in E} f(u,v) = \sum_{u \in S, v \in T} f(u,v) - \sum_{u \in T, v \in S} f(u,v)$$

由于 $f(u,v) \leq c(u,v)$ 且 $f(u,v) \geq 0$：

$$f \leq \sum_{u \in S, v \in T} c(u,v) = c(S, T)$$

**第二步：证明存在割使得 $f = c(S, T)$**

设 $f$ 为最大流，定义：
- $S$：从 $s$ 通过正残留容量边可达的节点集合
- $T = V \setminus S$

则：
$$f = \sum_{u \in S, v \in T} f(u,v) - \sum_{u \in T, v \in S} f(u,v) = c(S, T)$$

因为从 $T$ 到 $S$ 的边流量为0（否则 $S$ 的定义不成立）。

**作用：** 这个定理建立了最大流和最小割之间的对偶关系，为算法的正确性提供了理论基础。

### 8.2 棒球淘汰判定定理

**定理：** 球队 $s$ 被淘汰当且仅当存在一个割 $(S, T)$ 使得 $s \in T$ 且：

$$\sum_{i \in S} w_i > W_{max} \cdot |S| - R_S$$

**证明：**

**充分性：** 如果存在这样的割，说明集合 $S$ 中的球队已经赢了太多比赛，即使 $s$ 赢得所有剩余比赛也无法追上。

**必要性：** 如果 $s$ 被淘汰，根据最大流-最小割定理，存在最小割 $(S, T)$ 使得 $f^* = c(S, T) < R$。通过分析割的结构，可以证明上述不等式成立。

**作用：** 这个定理将组合优化问题转化为网络流问题，使得我们可以用高效的算法求解。

## 九、代码实现说明

### 9.1 算法思想与代码关系

**流网络构建（`BaseballElimination.solve`方法）：**

1. **节点编号方案：**
   ```python
   # 0: 源点
   # 1 ~ num_games: 比赛节点
   # num_games+1 ~ num_games+n: 球队节点
   # num_games+n+1: 汇点
   ```

2. **边的添加：**
   ```python
   # 源点到比赛节点
   solver.add_edge(source, game_node, cap)
   
   # 比赛节点到球队节点
   solver.add_edge(game_node, t1_idx, float('inf'))
   solver.add_edge(game_node, t2_idx, float('inf'))
   
   # 球队节点到汇点
   solver.add_edge(team_node, sink, cap)
   ```

3. **淘汰判定：**
   ```python
   eliminated = flow < total_remaining
   ```

**Dinic算法（`MaxFlowSolver`类）：**

1. **BFS分层（`bfs`方法）：**
   ```python
   def bfs(self, s, t, level):
       level[s] = 0
       queue = deque([s])
       while queue:
           u = queue.popleft()
           for v in self.graph[u]:
               if level[v] == -1 and self.graph[u][v] - self.flow[u][v] > 0:
                   level[v] = level[u] + 1
                   queue.append(v)
       return level[t] != -1
   ```

2. **DFS阻塞流（`dfs`方法）：**
   ```python
   def dfs(self, u, t, flow, level, start):
       if u == t:
           return flow
       while start[u] < len(self.graph[u]):
           v = list(self.graph[u].keys())[start[u]]
           if level[v] == level[u] + 1 and self.graph[u][v] - self.flow[u][v] > 0:
               pushed = self.dfs(v, t, min(flow, self.graph[u][v] - self.flow[u][v]), level, start)
               if pushed > 0:
                   self.flow[u][v] += pushed
                   self.flow[v][u] -= pushed
                   return pushed
           start[u] += 1
       return 0
   ```

3. **主循环（`max_flow`方法）：**
   ```python
   def max_flow(self, s, t):
       total_flow = 0
       level = [-1] * self.n
       while self.bfs(s, t, level):
           start = [0] * self.n
           while True:
               pushed = self.dfs(s, t, float('inf'), level, start)
               if pushed == 0:
                   break
               total_flow += pushed
       return total_flow
   ```

### 9.2 关键数据结构

```python
# 邻接表存储图
self.graph = defaultdict(dict)  # graph[u][v] = 容量
self.flow = defaultdict(dict)   # flow[u][v] = 当前流量

# 球队信息
self.wins = {}      # 当前胜场
```

### 12.3 Japan淘汰原因分析

根据普林斯顿课程的要求，用非技术性语言解释Japan为何被淘汰：

**淘汰证书：** R = { Poland, Russia, Brazil, Iran }

**分析过程：**

1. **Japan的最大可能胜场数：** 2 + 4 = 6场

2. **R集合的当前胜场数：**
   - Poland: 6胜
   - Russia: 5胜
   - Brazil: 5胜
   - Iran: 5胜
   - 合计：6 + 5 + 5 + 5 = 21胜

3. **R集合内部的剩余比赛场次：**
   - Poland vs Russia: 1场
   - Poland vs Brazil: 1场
   - Poland vs Iran: 0场
   - Russia vs Brazil: 1场
   - Russia vs Iran: 1场
   - Brazil vs Iran: 1场
   - 合计：1 + 1 + 0 + 1 + 1 + 1 = 5场

4. **R集合的最低胜场数：**
   - 当前胜场：21场
   - 内部比赛至少产生：5场胜利
   - 最低总胜场：21 + 5 = 26场

5. **平均胜场数：** 26 / 4 = 6.5场

**结论：** 无论如何安排比赛结果，R集合中的4支球队平均至少赢6.5场，意味着至少有一支球队会赢7场或更多。而Japan最多只能赢6场，因此Japan被淘汰。
