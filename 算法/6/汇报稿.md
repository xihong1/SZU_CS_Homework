## 第一部分：问题背景（2分钟）

### 1.1 什么是棒球淘汰问题？

在美国职业棒球大联盟中，每支球队要打162场比赛。赛季结束后，胜场数最多的球队获得冠军。

**关键问题：** 在赛季进行过程中，如何判断某支球队是否已经被"淘汰"——即无论剩余比赛结果如何，都不可能获得冠军？

### 1.2 实际案例

我使用了1996年NL West分区的真实数据：

| 球队 | 胜场 | 负场 | 剩余场次 |
|------|------|------|----------|
| Atlanta | 83 | 71 | 8 |
| Philly | 80 | 79 | 3 |
| NY | 78 | 78 | 6 |
| Montreal | 77 | 82 | 3 |

**表面观察：**
- Atlanta领先，83胜
- Montreal最多只能赢80场，似乎被淘汰
- 但Philly的情况更复杂——虽然理论上能赢83场，但实际情况如何？

## 第二部分：流网络构造原理（3分钟）

### 2.1 核心思想

将棒球淘汰问题转化为最大流问题：

1. **构建流网络**，其中：
   - 源点代表"比赛机会"
   - 比赛节点代表剩余比赛
   - 球队节点代表各支球队
   - 汇点代表"胜利分配"

2. **计算最大流**，判断是否等于总剩余比赛场次

### 2.2 网络结构

以判断Montreal是否被淘汰为例：

```
                    Atlanta vs Philly (1)
                   /        \
源点 s ---- g1 ---- g2 (Atlanta vs NY, 6)
        \        /
         g3 (Philly vs NY, 0)
         
         Atlanta (cap = 80-83 = -3) → 已超过，直接淘汰
```

### 2.3 容量设置

- **源点到比赛节点：** 容量 = 两队之间的剩余比赛场次
- **比赛节点到球队节点：** 容量 = ∞（不限制）
- **球队节点到汇点：** 容量 = 被判断球队的最大可能胜场数 - 该球队当前胜场数

**关键点：** 如果容量为负数，说明该球队已经超过被判断球队的最大可能胜场数，直接淘汰。

## 第三部分：最大流算法（4分钟）

### 3.1 最大流-最小割定理

**定理：** 在任意网络流中，从源点到汇点的最大流值等于最小割容量。

$$f^* = c^*(S, T)$$

**证明思路：**

1. **第一步：** 证明对于任意割 $(S, T)$，流值 $f \leq c(S, T)$
   - 流值等于从 $S$ 到 $T$ 的流量减去从 $T$ 到 $S$ 的流量
   - 由于容量限制，流值不会超过割容量

2. **第二步：** 证明存在割使得 $f = c(S, T)$
   - 定义 $S$ 为从源点通过正残留容量边可达的节点集合
   - 证明这个割的容量等于最大流值

**作用：** 这个定理建立了最大流和最小割之间的对偶关系，为算法正确性提供了理论基础。

### 3.2 Dinic算法

本实验采用Dinic算法，时间复杂度为 $O(V^2E)$。

**算法步骤：**

1. **构建分层图（BFS）：**
   - 从源点开始BFS，为每个节点分配层次
   - 只保留满足 $level[v] = level[u] + 1$ 的边
   - 保证增广路径长度单调递增

2. **DFS阻塞流：**
   - 在分层图上进行DFS，找到所有增广路径
   - 使用"当前弧优化"避免重复搜索
   - 一次DFS可以找到多条增广路径

3. **重复执行：**
   - 直到无法找到从源点到汇点的增广路径
   - 每次BFS后，至少存在一条增广路径

**关键代码片段：**

```python
def bfs(self, s, t, level):
    """BFS构建分层图"""
    level[s] = 0
    queue = deque([s])
    while queue:
        u = queue.popleft()
        for v in self.graph[u]:
            if level[v] == -1 and self.graph[u][v] - self.flow[u][v] > 0:
                level[v] = level[u] + 1
                queue.append(v)
    return level[t] != -1
```

### 3.3 为什么最大流能解决这个问题？

**流量守恒的意义：**
- 每场比赛的胜利必须分配给参赛的两支球队之一
- 不能有"凭空产生"的胜利
- 保证了比赛结果的合理性

**容量约束的意义：**
- 每支球队最多只能再赢 $W_{max} - w_i$ 场比赛
- 如果超过这个数量，说明已经超过被判断球队的最大可能胜场数
- 保证了淘汰判定的正确性

**判定条件：**
$$\text{Eliminated} \iff f^* < R$$

其中 $f^*$ 是最大流，$R$ 是总剩余比赛场次。

### 4.1 求解结果

运行代码后得到：

| 球队 | 最大可能胜场 | 最大流 | 总剩余比赛 | 状态 |
|------|------------|--------|-----------|------|
| Atlanta | 91 | 4 | 4 | 未淘汰 |
| Philly | 83 | 7 | 14 | 已淘汰 |
| NY | 84 | 8 | 8 | 未淘汰 |
| Montreal | 80 | 0 | 0 | 已淘汰 |

### 4.2 结果分析

**Montreal被直接淘汰：**
- Atlanta已经83胜，超过了Montreal的最大可能胜场数80
- 流网络中Atlanta到汇点的容量为负（80-83=-3）
- 最大流为0，小于总剩余比赛场次，确认淘汰

**Philly被间接淘汰：**
- 虽然Philly理论上能赢83场
- 但Atlanta和NY之间的6场比赛会导致至少一方获得额外胜场
- 最大流（7）小于总剩余比赛（14），说明存在无法安排的比赛
- 因此Philly被淘汰

**NY未被淘汰：**
- 如果Atlanta输掉所有比赛，NY有机会夺冠
- 最大流等于总剩余比赛场次，说明所有比赛都能安排

### 5.1 核心数据结构

```python
# 邻接表存储图
self.graph = defaultdict(dict)  # graph[u][v] = 容量
self.flow = defaultdict(dict)   # flow[u][v] = 当前流量

# 球队信息
self.wins = {}      # 当前胜场
self.losses = {}    # 当前负场
self.remaining = {} # 剩余场次
self.against = {}   # 对阵其他球队的剩余场次
```

### 5.2 流网络构建

```python
# 节点编号
# 0: 源点
# 1 ~ num_games: 比赛节点
# num_games+1 ~ num_games+n: 球队节点
# num_games+n+1: 汇点

# 添加边
solver.add_edge(source, game_node, cap)  # 源点到比赛节点
solver.add_edge(game_node, t1_idx, float('inf'))  # 比赛节点到球队节点
solver.add_edge(team_node, sink, cap)  # 球队节点到汇点
```
