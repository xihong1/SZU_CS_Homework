# 实验报告：无向图桥数求解

## 一、实验目的
1. 理解“桥”的定义与性质，掌握桥与环的关系。
2. 实现基准算法，并基于并查集设计更高效的算法（非 Tarjan）。
3. 在给定数据集上比较算法性能，并用图表展示结果。

## 二、实验环境
- 操作系统：macOS
- Python：3.10.19（conda）
- 运行时间统计：`time.perf_counter()`

## 三、数据集说明
- `mediumG.txt`：
  - 顶点数 $n=250$
  - 边数 $m=1273$
- `largeG.txt`：
  - 顶点数 $n=1{,}000{,}000$
  - 边数 $m=7{,}586{,}063$

文件格式：前两行为 $n$、$m$，之后每行一条无向边 $u\ v$。

## 四、算法设计
### 4.1 基准算法（逐边删除 + BFS）
**思想**：对每条边 $(u,v)$，暂时“删除”这条边，检查 $u$ 与 $v$ 是否仍连通。若不连通，则该边为桥。

**核心步骤**：
1. 读取所有边，建立带边编号的邻接表。
2. 对每条边执行一次 BFS/DFS（忽略该边）。
3. 若 $v$ 不可达，则该边为桥。

**伪代码**：
```
Baseline-Bridge-Count(G=(V,E))
  build adjacency list with edge id
  bridge_count = 0
  for each edge e=(u,v) with id
    mark all vertices unvisited
    BFS from u, ignoring edge id
    if v is not visited
      bridge_count += 1
  return bridge_count
```

**复杂度**：
- 时间复杂度：$O(m(n+m))$
- 空间复杂度：$O(n+m)$

### 4.2 并查集高效算法（生成树 + 非树边标记环）

**思想**：
1. 用并查集生成一棵（森林）生成树，所有非树边都形成”环”。
2. 对每条非树边 $(u,v)$，其在生成树上的路径上所有树边都不可能是桥。
3. 用”跳跃并查集（DSUJump）”加速标记路径上的树边。

**理论依据**：

算法基于以下关键引理：

> **引理**：设 $T$ 为图 $G$ 的一棵生成树（或森林）。对于任意一条树边 $e \in T$，$e$ 是桥当且仅当不存在非树边 $(u,v) \notin T$，使得 $e$ 位于 $u$ 到 $v$ 在 $T$ 上的唯一路径中。

**证明**：
- （$\Rightarrow$）若 $e$ 是桥，删除 $e$ 后图不连通。若存在非树边”覆盖” $e$，则删除 $e$ 后仍可通过该非树边连通两端，矛盾。
- （$\Leftarrow$）若 $e$ 不被任何非树边覆盖，则删除 $e$ 后，其两端点在 $T$ 上的路径断开，且图 $G$ 中无其他路径连接它们（否则该路径上的边与 $T$ 上的部分路径将形成一条非树边覆盖 $e$），矛盾。$\square$

因此，只需将生成树上被非树边”覆盖”的边标记为”非桥”，剩余的树边均为桥。

**核心数据结构**：

| 数据结构 | 作用 | 关键操作 |
|---|---|---|
| `DSU`（并查集） | 构建生成树、判定非树边 | `find(x)`：路径压缩查找；`union(a,b)`：按秩合并 |
| `DSUJump`（跳跃并查集） | 快速跳过已标记节点，避免重复遍历 | `find(x)`：跳至最近未标记祖先；`skip_to_parent(x, p)`：将 $x$ 直接链至父节点 |
| `tree_adj`（邻接表） | 存储生成树的拓扑结构 | 用于 DFS/BFS 计算 `parent` 和 `depth` |
| `parent[]` / `depth[]` | 记录树上每个节点的父节点和深度 | 支持沿深度向上遍历路径 |
| `marked[]` | 标记树边是否被非树边覆盖 | `True` 表示该树边不是桥 |

**核心步骤**：

1. **第一次扫描文件**：用 DSU 构建生成树。对每条边 $(u,v)$，若 $u$ 和 $v$ 不在同一集合，则将该边加入生成树并 `union`；否则该边为非树边（仅记录，不存储）。

2. **在生成树上 DFS/BFS**：计算每个节点的 `parent`（根节点的 `parent` 指向自身）与 `depth`。

3. **第二次扫描文件**：重新遍历所有边。对每条非树边 $(u,v)$，在生成树上将 $u$ 和 $v$ 分别沿 `parent` 向上跳，沿途将经过的节点标记为”已覆盖”（即该节点到其父节点的树边不是桥）。DSUJump 确保每条树边至多被标记一次。

4. **统计桥数**：遍历所有节点，若某节点的 `parent[node] != node`（非根）且 `marked[node] == false`（未被覆盖），则该节点到其父节点的树边是桥。

**算法执行示例**：

以图 2 的局部结构（路径 3-4-5，外加桥 3-9 与桥 4-10）为例，演示算法过程：

```
初始图：边集 = {(3,4), (4,5), (3,9), (4,10)}
```

- **Pass 1 — 构建生成树**：所有边均为树边（无环），生成树即原图本身。

```
parent:  3→3,  4→3,  5→4,  9→3,  10→4
depth:   3:0,  4:1,  5:2,  9:1,  10:2
```

- **Pass 2 — 标记覆盖**：无非树边，因此没有边被标记。

- **统计结果**：所有非根节点 $\{4,5,9,10\}$ 均未被标记 → 全部 4 条树边均为桥。

再考虑一个含环的例子：

```
边集 = {(0,1), (1,2), (2,0), (2,3)}
        树边    树边    非树边   树边
```

- **Pass 1**：$(0,1),(1,2),(2,3)$ 加入生成树；$(2,0)$ 为非树边（形成环 $0-1-2-0$）。

```
parent:  0→0,  1→0,  2→1,  3→2
depth:   0:0,  1:1,  2:2,  3:3
```

- **Pass 2**：处理非树边 $(2,0)$。$u=2, v=0$，$depth[2] > depth[0]$，标记 $2$（边 $2-1$ 被覆盖），$2$ 跳至 $1$。此时 $u=1, v=0$，$depth[1] > depth[0]$，标记 $1$（边 $1-0$ 被覆盖），$1$ 跳至 $0$。$u=0, v=0$，循环结束。

- **统计结果**：$marked[1]=T, marked[2]=T$，仅 $marked[3]=F$ → 桥数为 1（边 $3-2$）。

**DSUJump 优化分析**：

如果对每条非树边，采用朴素方法沿 `parent` 逐级向上标记，最坏情况下（如生成树退化为一条链）每次标记复杂度为 $O(n)$，$m$ 条非树边将导致总复杂度 $O(nm)$。

DSUJump 通过路径压缩解决此问题：当标记节点 $u$ 后，立即调用 `skip_to_parent(u, parent[u])` 将 $u$ 直接链接到其父节点，后续再经过 $u$ 时 `find(u)` 会直接跳至父节点。这保证了每个节点至多被标记一次，非树边路径标记的总开销降至 $O(n \cdot \alpha(n))$。

**两趟扫描策略**：

对于大规模图（如 `largeG.txt` 有 758 万条边），将全部边存入内存可能导致内存不足。本算法采用两趟文件扫描：
- 第一趟：仅存储生成树边（$n-1$ 条，$O(n)$ 空间）；
- 第二趟：重新读取文件，逐条处理非树边，无需存储。

这使得空间复杂度从 $O(n+m)$ 降至 $O(n)$。

**伪代码**：
```
DSU-Bridge-Count(G=(V,E))
  T = empty spanning forest
  DSU.init(|V|)
  for each edge (u,v) in E
    if DSU.union(u,v)
      add (u,v) to T
  compute parent[u], depth[u] on T

  mark[u] = false
  Jump.init(|V|)
  DSU2.init(|V|)
  for each edge (u,v) in E
    if DSU2.union(u,v) == false   # non-tree edge
      u = Jump.find(u); v = Jump.find(v)
      while u != v
        if depth[u] < depth[v]: swap(u,v)
        if parent[u] == u: break
        mark[u] = true
        Jump.parent[u] = parent[u]   # path compression to parent
        u = Jump.find(u)

  bridge_count = 0
  for each node u
    if parent[u] != u and mark[u] == false
      bridge_count += 1
  return bridge_count
```

**复杂度**：
- 时间复杂度：$O((n+m)\alpha(n))$
- 空间复杂度：$O(n)$（树结构 + 数组）

**关于 $\alpha(n)$ 的讨论**：
- $\alpha(n)$ 是阿克曼函数的反函数（Inverse Ackermann），增长极其缓慢。
- 阿克曼函数 $A(m,n)$ 是一个增长极快的递归函数，常见定义为：
  $$
  A(m,n)=
  \begin{cases}
  n+1, & m=0 \\
  A(m-1,1), & m>0,\ n=0 \\
  A(m-1, A(m,n-1)), & m>0,\ n>0
  \end{cases}
  $$
- 在并查集使用“路径压缩 + 按秩合并”的情况下，单次 `find/union` 的均摊复杂度为 $O(\alpha(n))$。
- 对任何现实规模的数据（即使 $n$ 达到 $10^{9}$ 或更大），$\alpha(n)$ 也不超过 5。
- 因此 $O((n+m)\alpha(n))$ 在实践中几乎等同于线性时间 $O(n+m)$。

### 4.3 与 Tarjan 算法的对比分析

Tarjan 算法是求解桥问题的经典算法，此处进行简要对比以说明两种思路的差异。

**Tarjan 算法思路**：
- 对图进行一次 DFS，记录每个节点的发现时间 `disc[u]` 和最早可达祖先 `low[u]`。
- 对于树边 $(u,v)$（$u$ 是 $v$ 的父节点），若 `low[v] > disc[u]`，则 $(u,v)$ 为桥。
- 时间复杂度 $O(n+m)$，空间复杂度 $O(n)$。

**本算法 vs Tarjan**：

| 维度 | Tarjan 算法 | 本算法（并查集） |
|---|---|---|
| 核心思想 | DFS 回溯，通过 low 值检测环 | 生成树 + 非树边覆盖标记 |
| 遍历次数 | 一次 DFS | 两次文件扫描 + 一次 DFS/BFS |
| 关键数据结构 | `disc[]`, `low[]`, 递归栈 | `DSU`, `DSUJump`, `parent[]`, `depth[]` |
| 递归依赖 | 依赖系统栈（大规模图可能栈溢出） | 显式栈 / 迭代，无递归栈溢出风险 |
| 实现复杂度 | 逻辑精简，但递归回溯较难调试 | 结构清晰，多个数据结构组合 |
| 时间复杂度 | $O(n+m)$ | $O((n+m)\alpha(n))$ |
| 空间复杂度 | $O(n)$ | $O(n)$ |

**为何本实验要求使用并查集而非 Tarjan**：
1. 并查集方法不依赖递归 DFS，对百万级节点的大图更安全（无栈溢出）；
2. 两趟扫描策略可处理超出内存容量的图（仅存储生成树）；
3. 通过组合多种数据结构解决问题，体现了算法设计的综合能力。

## 七、结论与分析
1. 基准算法实现简单但时间复杂度过高，仅适用于小规模图。
2. 使用并查集 + 生成树路径标记，可将复杂度降至近线性，显著提升性能。
3. 实验中 `mediumG.txt` 的运行时间差距约为 $\frac{0.085471}{0.001198}\approx 71.4$ 倍。

**典型问答记录**：

- 问：讨论并查集时间复杂度中的 $\alpha(n)$

- 答：$\alpha(n)$ 是阿克曼函数 $A(m,n)$ 的反函数（Inverse Ackermann），增长极其缓慢。阿克曼函数定义为：
  $$
  A(m,n)=
  \begin{cases}
  n+1, & m=0 \\
  A(m-1,1), & m>0,\ n=0 \\
  A(m-1, A(m,n-1)), & m>0,\ n>0
  \end{cases}
  $$
  该函数随 $m$ 和 $n$ 的增长极快地增长，例如 $A(4,2)$ 已是一个极为巨大的数。其反函数 $\alpha(n)$ 可理解为使得 $A(k, k) \geq n$ 的最小的 $k$。在并查集同时使用"路径压缩"和"按秩合并"优化时，单次 `find` 或 `union` 操作的均摊时间复杂度为 $O(\alpha(n))$。由于 $\alpha(n)$ 增长极慢，对所有现实中可能出现的数据规模（即便 $n$ 达到 $10^9$ 甚至宇宙原子总数级），$\alpha(n)$ 的值都不超过 5，因此 $O((n+m)\alpha(n))$ 在实践中几乎等同于线性时间 $O(n+m)$。这正是本实验高效算法能在 8.5 秒内处理千万级边的原因之一。
