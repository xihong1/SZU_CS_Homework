# NovaLang 语言设计文档

## 1. 语言定位与设计哲学

### 1.1 语言定位
NovaLang 是一门面向编译原理教学场景设计的静态强类型语言。它面向的核心用户不是通用应用开发者，而是需要在一个学期内完成词法分析、语法分析、语义分析与代码生成全链路实验的学生与课程团队。语言的目标并非覆盖工业语言的全部特性，而是做到三件事：

1. 语法结构清晰，便于构造可解释、可调试的前端实现。
2. 类型信息显式，能够在语义阶段形成高密度、可定位的错误报告。
3. 语义机制有创新点，能够在答辩中体现设计思考，而不只是复刻既有语言。

NovaLang 的核心创新是安全提醒机制，即变量声明时不携带后缀，但变量使用时强制写出 @类型。该机制把类型信息从“声明处的一次性信息”提升为“每一次使用的持续性约束”，对教学中的类型追踪、类型一致性验证、报错定位都有直接价值。

### 1.2 设计原则

1. 极简结构优先。
采用冒号加缩进描述代码块，不使用分号与大括号，减少语法噪声，强化结构可读性。

2. 显式类型优先。
所有变量先声明类型；每次使用变量都要带 @类型后缀，避免阅读时上下文猜测。

3. 统一调用风格。
函数调用统一为 箭头调用，即 函数名->(参数列表)，让“声明箭头”与“调用箭头”形成成对记忆。

4. 万物对象化。
类型转换不允许 C 风格强转，不允许括号强转，必须通过对象方法完成，如 x@int.toFloat()。

5. 运算符兼容迁移。
运算符完全采用 C++ 风格，降低学习与迁移成本，便于将教学重点集中在语义规则而非运算符记忆。

### 1.3 与 C++、Python、Java 的对比

与 C++ 的关系：

1. 相同点：强类型、数组声明风格、运算符集合。
2. 不同点：不使用分号和大括号；不允许 C 风格强转；函数调用使用 -> 而非 ()。

与 Python 的关系：

1. 相同点：缩进定义代码块，冒号引导块体。
2. 不同点：类型是强制显式的，不是动态类型；变量使用需附带 @类型提醒。

与 Java 的关系：

1. 相同点：强调对象方法完成能力变换，尤其是类型转换。
2. 不同点：语法更紧凑，不依赖类作为最外层组织；函数式入口保持接近 C/C++ 主函数范式。

### 1.4 适用场景与不适用场景

适用场景：

1. 编译课程实验和答辩演示。
2. 需要显式类型追踪的教学评测。
3. 需要构造高质量错误程序样例的语义实验。

不适用场景：

1. 大型工业项目开发。
2. 需要复杂并发库、模块系统、泛型系统的业务工程。
3. 对运行时性能有严格要求的生产环境。

### 2.4 注释格式（与 C++ 一致）

1. 单行注释：以 // 开始，到行末结束。
2. 多行注释：以 /* 开始，以 */ 结束，不支持嵌套。

### 2.5 词法约束细则

1. 缩进建议统一为 4 空格，禁止混用 Tab 与空格。
2. 同一代码块内必须保持相同缩进深度。
3. 每个控制语句头（if/else/while/fn）以冒号结束并换行。
4. 数组整体引用必须写作 标识符@类型[长度]，如 a@int[5]。
5. 数组元素引用必须写作 标识符[索引表达式]@类型，如 a[1]@int。

## 3. 语法规范（EBNF）

完整 EBNF 请见 grammar.ebnf。以下为关键结构摘要。

1. 程序由多个顶层函数定义构成。
2. 程序入口函数必须存在，签名为 fn(void) main ->:。
3. 函数定义语法：fn(返回类型) 函数名 -> 参数列表:。
4. 参数形态：参数名@类型。
5. 语句包含：声明、赋值、返回、函数调用、if、while。
6. 表达式使用标准优先级分层，兼容 C++ 运算符体系。

### 3.1 运算符优先级与结合性

从高到低：

1. 后缀层：数组下标、类型后缀、成员访问、方法调用、函数调用。
结合性：左结合。

2. 一元层：!、一元 -。
结合性：右结合。

3. 乘法层：*、/、%。
结合性：左结合。

4. 加法层：+、-。
结合性：左结合。

5. 关系层：<、<=、>、>=。
结合性：左结合。

6. 相等层：==、!=。
结合性：左结合。

7. 逻辑与层：&&。
结合性：左结合。

8. 逻辑或层：||。
结合性：左结合。

赋值符号 = 不放在表达式层，作为赋值语句专用，避免歧义。

### 3.2 类型系统与转换约束

1. 基础类型：int、float、string、bool、void。
2. 数组类型：基础类型加固定长度，例如 int[5]。
3. 禁止 C 风格强转，如 (float)a@int。
4. 强制方法转换：
   - int 到 float：x@int.toFloat()
   - float 到 int：y@float.toInt()
5. 语义阶段应检查：
   - 赋值两侧类型兼容。
   - 函数实参与形参类型、数量一致。
   - 返回类型与函数声明一致。
   - 条件表达式必须是 bool。

## 5. 编译实现建议

### 5.1 词法阶段

1. 先做行级切分，再依据缩进栈发射 INDENT/DEDENT。
2. 对 组合符号 ->、<=、>=、==、!=、&&、|| 做最长匹配。
3. 对 标识符@类型、数组元素访问、数组整体引用分别归一化为可复用 token 序列。

### 5.2 语法阶段

1. 推荐递归下降实现，按优先级分层处理表达式。
2. 将赋值语句和表达式语句分离，减少冲突。
3. 块结构统一由 NEWLINE+INDENT+DEDENT 控制。

### 5.3 语义阶段

1. 维护作用域栈，进入缩进块 push，退出块 pop。
2. 符号表记录标识符原名与声明类型。
3. 使用位置出现 @类型 后缀时，检查后缀类型与声明类型一致。
4. 方法调用 toFloat/toInt 检查接收者类型与目标类型合法性。

## 6. 语言总结

NovaLang 把缩进结构、显式类型与对象化转换组合在一起，形成一门兼具教学友好性和设计辨识度的实验语言。它在不显著增加语法复杂度的前提下，强化了类型系统在“声明-使用-转换”全链路上的可观测性。这一特点使其特别适合作为编译原理课程中的长期实验载体。

## 7. 语义规则细化与静态检查策略

为了确保语言不仅在语法层可解析，而且在语义层可验证，NovaLang 需要在编译前端建立一套明确、可执行、可复现实验结果的静态检查规则。以下规则可直接映射为语义分析阶段的检查点。

### 7.1 标识符声明与可见性规则

1. 变量在首次使用前必须完成声明，且声明必须位于可见作用域内。
2. 作用域边界由缩进块决定。函数体、if 分支体、while 体都引入新作用域。
3. 内层作用域允许定义与外层同名变量，视为变量遮蔽。遮蔽后，内层引用优先命中内层符号。
4. 离开作用域后，内层符号立即失效，不得被后续语句访问。
5. 同一作用域内不允许重复声明同名变量，否则应报语义错误。

### 7.2 安全提醒机制一致性规则

1. 变量声明形式为 类型 名称，例如 int a。
2. 使用变量时必须书写后缀类型，即 名称@类型。
3. 若后缀类型与声明类型不一致，必须报类型不一致错误。
4. 对数组元素访问写作 a[expr]@int 时，后缀类型必须与数组元素真实类型一致。
5. 对数组整体引用写作 a@int[5] 时，基础类型和长度都必须与声明一致。

该机制的价值在于把“类型正确性”从声明点扩展到每个使用点，能有效减少因阅读上下文丢失造成的误判。在答辩演示中，这一机制也非常利于解释语义检查流程。

### 7.3 表达式类型推导规则

1. 算术运算 + - * / % 的两个操作数应为数值类型。
2. 逻辑运算 && || ! 的操作数应为 bool 类型。
3. 关系运算和相等运算的两侧应满足可比较性约束。
4. if 与 while 条件表达式结果必须为 bool。
5. 赋值语句左值与右值类型必须兼容，不兼容时报错。

建议在实现中采用自底向上的表达式类型推导：先推导子表达式，再在父节点合并规则。这样可获得更稳定的错误定位能力。

### 7.4 函数语义规则

1. 函数签名由函数名、参数类型序列、返回类型共同决定。
2. 函数调用时，实参数量必须与形参数量一致。
3. 参数类型需逐一匹配，不允许隐式宽松转换。
4. 非 void 函数必须在所有可达路径返回值。
5. void 函数不应返回值表达式。

### 7.5 类型转换语义规则

1. 禁止 C 风格强制类型转换。
2. 合法转换通过对象方法调用表达，如 x@int.toFloat()。
3. toFloat 的接收者必须是 int，结果类型为 float。
4. toInt 的接收者必须是 float，结果类型为 int。
5. 对 string 与 bool 的转换策略可在后续版本扩展，但在当前版本应保持保守，避免引入未定义行为。

### 7.6 数组语义规则

1. 数组长度在声明时固定，必须是正整数常量。
2. a[i]@T 中 i 的类型应为 int。
3. 当索引可在编译期确定时，编译器可提前进行越界检查提示。
4. 作为参数传递时，a@T[n] 必须与形参数组类型完全一致。
5. 数组元素赋值应满足元素类型一致性，不允许跨类型直接赋值。

## 8. 错误模型与诊断输出规范

为了提高实验可评测性，NovaLang 建议采用分阶段错误分类模型，并保持统一诊断格式。推荐包含如下信息：错误阶段、行号、列号、错误码、简要说明、上下文片段。

### 8.1 词法错误

典型场景：

1. 非法字符。
2. 字符串未闭合。
3. 块注释未闭合。
4. 缩进不一致导致词法块结构异常。

建议输出示例：

1. [LEX001] 行 12 列 8：检测到非法字符。
2. [LEX002] 行 25 列 3：字符串字面量未闭合。

### 8.2 语法错误

典型场景：

1. if 或 while 语句头缺少冒号。
2. 函数定义头格式不匹配。
3. 调用箭头语法错误。
4. 缩进块起止不匹配。

建议采用同步恢复策略：在出现语法错误后跳过到下一行或下一语句起点，尽可能继续分析，提升一次编译发现问题数量。

### 8.3 语义错误

典型场景：

1. 未声明变量直接使用。
2. 使用后缀类型与声明类型不一致。
3. 不允许的类型赋值。
4. 函数参数数量或类型不匹配。
5. 非法类型转换调用。

语义错误建议以规则编号驱动，便于后续测试集自动比对。

## 9. 课程实验实施路线与复杂度评估

### 9.1 词法分析实现路线

1. 按行扫描输入并生成基础 token。
2. 使用缩进栈计算 INDENT 与 DEDENT。
3. 对多字符运算符进行最长匹配。
4. 识别并保留注释位置信息以便调试。

复杂度通常为线性时间，空间复杂度与 token 数量线性相关。

### 9.2 语法分析实现路线

1. 推荐递归下降方法，结构与语法规则一一对应。
2. 表达式采用优先级分层函数，避免左递归。
3. 语句块由 INDENT 与 DEDENT 驱动，简化块边界判断。

在无回溯设计下，整体可维持近似线性分析性能。

### 9.3 语义分析实现路线

1. 构建多层符号表并维护作用域栈。
2. 对每个表达式节点计算静态类型。
3. 对函数调用做签名匹配。
4. 对类型转换做白名单检查。

语义分析通常随抽象语法树遍历完成，时间复杂度与语法树规模线性相关。

### 9.4 面向代码生成阶段的接口建议

1. 为每个表达式节点附加静态类型属性。
2. 为每个变量绑定唯一符号编号，便于中间代码生成。
3. 对控制流节点记录入口与出口标签信息。
4. 为函数调用节点保留参数求值顺序元数据。

这些信息可直接降低后续三地址码生成的复杂度。

## 10. 可扩展性与后续版本规划

NovaLang 当前版本聚焦教学主线，后续可在不破坏核心语法风格的前提下迭代扩展：

1. 引入 for 循环语法糖。
2. 引入结构体与成员方法。
3. 引入模块导入机制。
4. 引入基础标准库与错误处理约定。
5. 引入更细粒度的类型转换规则与警告级别。

扩展原则是保证原有代码可迁移、原有诊断规则可复用、原有测试场景可继续运行。通过这一策略，语言能够在课程进度推进中保持稳定演化，而不会因为语法大改导致实验链路中断。
