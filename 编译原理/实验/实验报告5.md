## 1. 任务一：中间代码生成器实现

### 1.1 后端策略选择与IR指令集设计

选择了**三地址码（Three-Address Code, TAC）**作为中间表示。TAC指令的形式为 `result = op arg1, arg2`，每条指令最多三个操作数。选择理由：1）形式统一，接近汇编但独立于具体机器；2）便于实现数据流分析和基于DAG的代码优化；3）在编译原理教材中最为常用；4）与NovaLang的表达式结构自然对应。

设计了18种TAC指令，覆盖数据移动、算术运算、比较运算、逻辑运算、控制流跳转、函数调用、数组操作和类型转换。完整指令集文档见ir-design.md。

具体代码实现——TACGen类作为生成器核心，维护指令列表、临时变量计数器和标签计数器：

```python
class TACGen:
    def __init__(self):
        self.instructions = []    # 指令列表
        self.temp_counter = 0     # 临时变量编号 t0, t1, ...
        self.label_counter = 0    # 标签编号 L0, L1, ...

    def new_temp(self):
        t = f"t{self.temp_counter}"
        self.temp_counter += 1
        return t

    def new_label(self, prefix="L"):
        lbl = f"{prefix}{self.label_counter}"
        self.label_counter += 1
        return lbl

    def emit(self, op, args=None, result=None):
        """发射一条TAC指令"""
        self.instructions.append({"op": op, "args": args or [], "result": result})
```

### 1.2 表达式翻译

表达式翻译采用**后序遍历AST**的递归策略。`_gen_expr()` 方法根据节点类型递归生成子表达式代码，为每个子表达式分配临时变量，最终返回代表该表达式值的操作数名。

具体代码实现——`_gen_expr()` 分发器：

```python
def _gen_expr(self, node):
    t = node.get("type", "")
    # 字面量：生成li指令加载到临时变量
    if t == "IntLiteral":
        tmp = self.new_temp()
        self.emit("li", args=[node.get("value")], result=tmp)
        return tmp
    # 标识符引用：直接返回变量名（无需临时变量）
    elif t == "TypedVarRef":
        return node.get("name", "")
    # 二元表达式：递归翻译左右子树，生成运算指令
    elif t == "BinaryExpr":
        return self._gen_binary(node)
    # 函数调用：传递参数+call指令
    elif t == "CallExpr":
        return self._gen_call(node)
```

**运算符优先级与结合性**：由于翻译基于实验三的AST（已正确处理优先级和结合性），代码生成阶段无需再次处理——AST中 `a + b * c` 已被解析为 `BinaryExpr(+, a, BinaryExpr(*, b, c))`，翻译时自然生成正确的代码顺序。

二元表达式翻译：

```python
def _gen_binary(self, node):
    op = node.get("op", "")
    left_result = self._gen_expr(node.get("left"))
    right_result = self._gen_expr(node.get("right"))
    tmp = self.new_temp()
    op_map = {"+": "add", "-": "sub", "*": "mul", "/": "div", "%": "mod",
              "<": "lt", "<=": "le", ">": "gt", ">=": "ge",
              "==": "eq", "!=": "ne", "&&": "and_", "||": "or_"}
    self.emit(op_map.get(op, "add"), args=[left_result, right_result], result=tmp)
    return tmp
```

### 1.3 控制流翻译

**if语句翻译**：生成条件判断代码后，用 `if_false`（jz）实现条件跳转。若条件为假则跳过then分支。若有else分支，则在then末尾加 `goto` 跳过else。

```python
def _gen_if(self, node):
    label_else = self.new_label("else")
    label_end = self.new_label("endif")
    cond_result = self._gen_expr(node.get("cond"))
    if else_body:
        self.emit("jz", args=[cond_result], result=label_else)  # 条件假→跳else
        self._gen_stmt_list(then_body)
        self.emit("jmp", result=label_end)                       # then结束→跳end
        self.emit_label(label_else)
        self._gen_stmt_list(else_body)
        self.emit_label(label_end)
    else:
        self.emit("jz", args=[cond_result], result=label_end)
        self._gen_stmt_list(then_body)
        self.emit_label(label_end)
```

以 `if x > 0: y = 1 else: y = 2` 为例，生成的TAC为：
```
    t0 = x > 0
    if_false t0 goto else0
    y = 1
    goto endif1
else0:
    y = 2
endif1:
```

**while循环翻译**：生成循环头标签、条件判断、条件跳转到循环尾、循环体、回跳。

```python
def _gen_while(self, node):
    label_start = self.new_label("while")
    label_end = self.new_label("wend")
    self.emit_label(label_start)
    cond_result = self._gen_expr(node.get("cond"))
    self.emit("jz", args=[cond_result], result=label_end)  # 条件假→退出循环
    self._gen_stmt_list(body)
    self.emit("jmp", result=label_start)                    # 回跳到循环头
    self.emit_label(label_end)
```

## 2. 任务二：代码优化

实现了4种代码优化，采用**迭代执行**策略：多个优化pass在循环中交替执行，直到收敛（不再产生新变化）或达到最大迭代次数（5轮）。

```python
def optimize(self):
    changed = True
    iteration = 0
    while changed and iteration < 5:
        changed = False
        if self._constant_folding():       changed = True
        if self._constant_propagation():   changed = True
        if self._algebraic_simplify():     changed = True
        iteration += 1
    self._dead_code_elimination()  # 最后执行一次
    return self.instructions
```

**为什么需要迭代**：一次优化可能为另一次优化创造机会。例如常量传播把 `x` 替换为 `5` 后，`5 * 2` 变成了两个常量相乘——常量折叠就可以接着把它化简为 `10`。

### 2.1 常量折叠 (Constant Folding)

**原理**：编译期计算常量表达式。扫描每条二元运算指令，如果两个操作数都能求值为编译期常量，直接计算结果并替换为 `li`（加载立即数）指令，消除运行时计算。

```python
def _constant_folding(self):
    changed = False
    for inst in self.instructions:
        op = inst.get("op", "")
        if op in ("add", "sub", "mul", "div", "mod",
                  "lt", "le", "gt", "ge", "eq", "ne", "and_", "or_"):
            args = inst.get("args", [])
            if len(args) == 2:
                val_a = self._get_const(args[0])   # 尝试解析为Python数值
                val_b = self._get_const(args[1])
                if val_a is not None and val_b is not None:
                    # 两个操作数都是常量 → 编译期求值
                    new_val = self._eval_const(op, val_a, val_b)
                    inst["op"] = "li"              # 替换为立即数加载
                    inst["args"] = [str(new_val).lower()
                                   if isinstance(new_val, bool) else str(new_val)]
                    changed = True
    return changed
```

**折叠效果示例**：

```
折叠前:                         折叠后:
    t0 = 2                          t2 = 6         ← 2*3 直接算出 6
    t1 = 3
    t2 = t0 * t1

    t0 = 1                          t1 = true      ← 3 > 1 直接算出 true
    t1 = 3 > t0
```

### 2.2 常量传播 (Constant Propagation)

**原理**：如果某个临时变量的值已知（由 `li` 加载或由 `mov` 从已知常量复制），则在后续使用该变量的地方直接替换为常量值。这减少了间接引用，并为常量折叠创造更多机会。

**关键约束**：常量表只追踪临时变量（`t` 开头），不追踪用户变量。这是为了避免将 `main` 中的 `n = 8` 错误地传播到 `fib` 的参数 `n` 上——两者是同名的不同变量。

```python
def _constant_propagation(self):
    changed = False
    for inst in self.instructions:
        if inst.get("op") == "li":
            result = inst.get("result")
            if result and result.startswith("t"):        # ★ 只追踪临时变量
                self.const_table[result] = self._parse_value(inst["args"][0])
        elif inst.get("op") == "mov":
            result = inst.get("result")
            if result and result.startswith("t"):
                src = inst["args"][0]
                if src in self.const_table:
                    self.const_table[result] = self.const_table[src]
        elif inst.get("op") not in ("label", "jmp", "jz", "jnz", "param",
                                     "call", "print_", "ret", "retv",
                                     "enter_func", "alloc", "alloc_array", "store"):
            result = inst.get("result")
            if result and result in self.const_table:
                del self.const_table[result]
    for inst in self.instructions:
        op = inst.get("op", "")
        if op in ("add", "sub", "mul", "div", "mod",
                  "lt", "le", "gt", "ge", "eq", "ne", "and_", "or_",
                  "mov", "store", "load", "neg", "not_",
                  "toFloat", "toInt", "print_", "param", "ret"):
            for i, arg in enumerate(inst.get("args", [])):
                if arg in self.const_table:
                    inst["args"][i] = str(self.const_table[arg])
                    changed = True
    return changed
```

**传播效果示例**：

```
传播前:                         传播后:
    t14 = 5                         param 5        ← 不再需要临时变量
    param t14
    t10 = call func_fib, 1          t10 = call func_fib, 1
```

### 2.3 代数化简 (Algebraic Simplification)

**原理**：利用代数恒等式消除冗余运算。匹配特定的指令模式，替换为更简单的等价形式。

```python
def _algebraic_simplify(self):
    changed = False
    for inst in self.instructions:
        op = inst.get("op", "")
        args = inst.get("args", [])
        if len(args) == 2:
            a, b = args[0], args[1]
            va, vb = self._get_const(a), self._get_const(b)
            if op == "mul":
                if vb == 1:       # x * 1 → x
                    inst["op"] = "mov"; inst["args"] = [a]; changed = True
                elif va == 1:     # 1 * x → x
                    inst["op"] = "mov"; inst["args"] = [b]; changed = True
                elif vb == 0 or va == 0:  # x * 0 → 0
                    inst["op"] = "li"; inst["args"] = ["0"]; changed = True
            elif op == "add":
                if vb == 0:       # x + 0 → x
                    inst["op"] = "mov"; inst["args"] = [a]; changed = True
                elif va == 0:     # 0 + x → x
                    inst["op"] = "mov"; inst["args"] = [b]; changed = True
            elif op == "sub":
                if vb == 0:       # x - 0 → x
                    inst["op"] = "mov"; inst["args"] = [a]; changed = True
            elif op == "div":
                if vb == 1:       # x / 1 → x
                    inst["op"] = "mov"; inst["args"] = [a]; changed = True
    return changed
```

支持的恒等式：

| 原始 | 化简 | 条件 |
|------|------|------|
| `x * 1` | `x` | 右操作数为 1 |
| `1 * x` | `x` | 左操作数为 1 |
| `x * 0` | `0` | 任一操作数为 0 |
| `x + 0` | `x` | 右操作数为 0 |
| `0 + x` | `x` | 左操作数为 0 |
| `x - 0` | `x` | 右操作数为 0 |
| `x / 1` | `x` | 右操作数为 1 |

化简后 `mul/add/sub/div` 被替换为 `mov`（直接复制）或 `li`（加载零），省掉一次完整的算术运算。

### 2.4 死代码消除 (Dead Code Elimination)

**原理**：如果一个临时变量的赋值从未被任何后续指令引用，这条赋值就是"死代码"——可以安全删除，因为它对程序输出没有任何影响。

```python
def _dead_code_elimination(self):
    used = set()
    for inst in self.instructions:
        for arg in inst.get("args", []):
            used.add(arg)
        if inst.get("op") in ("jmp", "jz", "jnz"):
            used.add(inst.get("result", ""))
    new_insts = []
    for inst in self.instructions:
        op = inst.get("op", "")
        result = inst.get("result", "")
        if op in ("label", "jmp", "jz", "jnz", "param", "call",
                   "print_", "ret", "retv", "enter_func",
                   "alloc", "alloc_array", "store"):
            new_insts.append(inst)
        elif result and result.startswith("t") and result not in used:
            continue  # ← 临死变量从未被使用，丢弃
        else:
            new_insts.append(inst)
    self.instructions = new_insts
```

**关键设计**：只删除**临时变量**（`t` 开头）的死赋值。用户变量（如 `x`、`answer`）即使当前未被引用也保留——因为它们是程序语义的一部分（可能在后续阶段有用）。有副作用的指令（跳转、调用、输出等）无条件保留。

## 3. 任务三：选做——IR解释执行（虚拟机）

实现了一个**基于 fetch-decode-execute 循环的虚拟机**，能够直接执行生成的 TAC 指令并输出程序运行结果。命令为 `python compiler.py run input.src`，支持 `--optimize` 标志运行优化后的 IR。

### 3.1 虚拟机架构

虚拟机不是递归遍历 AST，而是维护显式的程序状态，逐条取指-译码-执行：

```
┌─────────────────────────────────────────────┐
│  TACInterpreter (虚拟机)                    │
│                                             │
│  memory:     {"n":8, "t0":1, "answer":21}  │ ← 平铺内存
│  arrays:     {"a": [1, 2, 3, 4, 5]}        │ ← 数组存储
│  labels:     {"func_fib":0, "endif1":7, ...}│ ← 标签→指令索引
│                                             │
│  param_stack: [8, 5]    ← 函数参数传递栈    │
│  ret_stack:   [25, 11]  ← 返回地址栈        │
│  saved_mem:   [{...}]   ← 内存快照栈(调用上下文) │
│                                             │
│  ip: 15                  ← 指令指针(PC)      │
│  output: ["21"]          ← print输出收集     │
└─────────────────────────────────────────────┘
```

五个核心组件：

| 组件 | 类型 | 作用 |
|------|------|------|
| `memory` | `dict` | 平铺内存，变量名→值。所有函数共享同一内存空间 |
| `labels` | `dict` | 标签→指令索引表。初始化时扫描所有 label 指令建立 |
| `param_stack` | `list` | 参数传递栈。`param` 指令压入，`call` 指令弹出 |
| `ret_stack` | `list` | 返回地址栈。`call` 压入调用点IP，`ret` 弹出恢复 |
| `saved_mem` | `list` | 内存快照栈。`call` 保存调用者全部内存，`ret` 恢复 |

### 3.2 主循环：Fetch-Decode-Execute

```python
def run(self):
    self.ip = self.labels["func_main"] + 1   # 从 main 函数入口开始
    while self.ip < len(self.instructions):   # 主循环
        inst = self.instructions[self.ip]     # ★ FETCH: 取指令
        op = inst["op"]                       # ★ DECODE: 读操作码
        args = inst["args"]
        result = inst["result"]

        if op == "li":                        # ★ EXECUTE: 执行
            self.memory[result] = parse_literal(args[0])
        elif op == "add":
            self.memory[result] = memory[args[0]] + memory[args[1]]
        elif op == "jz":
            if not memory[args[0]]:
                self.ip = labels[result]       # 条件跳转
                continue                        # 跳过 ip += 1
        elif op == "call":
            saved_mem.append(dict(memory))     # 保存调用者上下文
            memory[param_name] = pop_param()   # 传入参数
            ip = find_func_start(label)        # 跳转到函数体
            continue
        elif op == "ret":
            memory = saved_mem.pop()           # 恢复调用者上下文
            memory[caller_result] = ret_val    # 写入返回值
            ip = ret_stack.pop()               # 跳回调用者
        self.ip += 1                           # 下一条指令
```

### 3.3 函数调用机制：完整内存快照

函数调用是虚拟机最复杂的操作。本实现采用**完整内存快照**方案：每次调用前保存整个 `memory` 字典的深拷贝，返回时完整替换恢复。

以 `fib(7)` 调用 `fib(6)` 为例，追踪虚拟机的完整状态变化：

```
Step 1: fib(7) 执行到 call 指令 (ip=11)
┌──────────────────────────────────────────┐
│ memory: {n:7, t0:1, t1:false, t2:1,    │ ← fib(7) 当前状态
│          t3:6}                           │
│ param_stack: [6]                         │ ← 参数 n-1=6 已入栈
│                                          │
│ ★ call func_fib, 1 执行:                │
│   ① ret_stack.append(11)                │ ← 记住返回地址
│   ② saved_mem.append(dict(memory))      │ ← 快照: {n:7, t0:1, ...}
│   ③ memory["n"] = 6                     │ ← 设置 fib(6) 的参数
│   ④ ip = 3  (跳过 label/enter/alloc)    │ ← 跳转到 fib 第一条指令
│   ⑤ continue                            │
└──────────────────────────────────────────┘

Step 2: fib(6) 递归执行...
    n=6: t0=1, t1=false, jz→endif
    递归调用 fib(5) 和 fib(4)
    结果: t4=fib(5)=5, t7=fib(4)=3, t8=8

Step 3: fib(6) 执行 ret t8 (ip=17)
┌──────────────────────────────────────────┐
│ ★ ret t8 执行:                           │
│   ① ret_val = memory["t8"] = 8          │ ← fib(6) 的返回值
│   ② memory = saved_mem.pop()            │ ← ★ 恢复 fib(7) 完整内存!
│      → {n:7, t0:1, t1:false, t2:1, t3:6}│
│   ③ caller_ip = ret_stack.pop() = 11    │ ← 回到 call 指令处
│   ④ memory["t4"] = 8                   │ ← 将返回值写入 fib(7) 的 t4
│   ⑤ ip = 11                             │
└──────────────────────────────────────────┘

Step 4: fib(7) 从 ip=12 继续执行
    t5=2, t6=n-2=5, param 5
    call fib(5) → t7=5
    t8 = t4+t7 = 8+5 = 13
    ret 13 → 返回到 fib(8)
```

**为什么用完整快照而不是栈帧**：完整快照方案极其简洁——5行代码实现调用上下文切换。代价是每次调用深拷贝整个内存字典（fib(8)约600次调用，每次~10个变量），对教学规模程序完全可接受。

### 3.5 遇到的关键Bug及修复

**Bug：递归调用中临时变量值泄漏**

现象：`fib(4)` 输出正确（3），但 `fib(8)` 输出错误（4 而非 21）。递归越深偏差越大。

根因：`run()` 方法中 call 处理器只保存了**参数变量**的值，没有保存完整内存快照。`fib(7)` 调用 `fib(6)` 时只保存了 `n=7`，但 `fib(6)` 执行期间修改了全部临时变量 `t0~t8`。返回时只恢复了 `n=7`，所有临时变量仍是 `fib(6)` 的脏值，导致 `fib(7)` 的后续计算使用错误数据。

修复：改为保存 `dict(self.memory)` 完整快照，返回时 `self.memory = self.saved_mem.pop()` 整体替换。修复后所有递归测试通过：`fib(3)=2, fib(4)=3, fib(5)=5, fib(6)=8, fib(7)=13, fib(8)=21`。同时修复了 `param_stack` 变量名写错（写成 `call_stack`）和 `ret` 只逐字段恢复的问题。

## 5. 设计与实现说明

### 5.1 后端策略选择

选择三地址码。相比字节码，TAC更接近高级语言的表达方式，每条指令的语义更清晰，优化pass更容易编写。相比直接解释AST，TAC为后续可能的目标代码生成（如汇编）提供了更好的中间层。

### 5.2 IR指令集设计

设计了18种TAC操作码，分为8类：数据移动、算术运算、比较运算、逻辑运算、控制流、函数调用、数组操作、类型转换。指令内部表示为Python dict，便于序列化和优化pass的遍历修改。

### 5.3 表达式与控制流翻译

表达式翻译采用后序遍历AST的递归策略，保证子表达式在父表达式之前求值。控制流翻译遵循标准模式——if用条件跳转+标签，while用循环头标签+条件跳转+回跳。临时变量从t0递增分配，标签从L0递增命名。

### 5.4 优化实现

实现了4种优化pass，采取迭代执行策略（重复直到收敛，最多5轮）。常量折叠和常量传播在循环中交替执行，代数化简并行执行，死代码消除在最后执行一次。

### 5.5 完整编译器流程回顾

```
源代码 → 词法分析(实验二) → Token序列
       → 语法分析(实验三) → AST
       → 语义分析(实验四) → 符号表 + 类型信息
       → 代码生成(实验五) → TAC中间代码 → 优化 → 最终IR
```

各阶段接口：词法→Token列表，语法→AST JSON，语义→符号表+类型标注（嵌入AST），代码生成→TAC指令列表。
