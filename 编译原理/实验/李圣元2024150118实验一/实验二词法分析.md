# 实验二：词法分析

## 一、实验概述

本实验是编译原理实验系列的第二个实验。在实验一中，你已经设计了自己的编程语言并完成了语言规范文档。本实验的目标是：根据你的词法规范，实现一个完整的词法分析器（Scanner），将源代码转换为Token序列。

词法分析是编译器的第一个阶段，负责将字符流转换为有意义的词法单元（Token）。一个好的词法分析器不仅要正确识别合法的Token，还要能够优雅地处理词法错误，提供有意义的错误信息。

## 二、实验目标

二、实验目标- 理解词法分析的基本原理：正则表达式、有限自动机（NFA/DFA）与Token识别的关系- 掌握最长匹配原则及其在词法分析中的应用- 能够实现一个完整的词法分析器，支持错误检测与报告- 理解词法分析器与语法分析器之间的接口设计

## 3. 必做功能

## （1）基本Token识别

- 关键字识别：区分关键字与标识符- 数字字面量：支持整数，如果你的语言有浮点数则需支持- 字符串字面量：支持转义字符（至少\n，\t，\l，\r）- 运算符和分隔符：包括多字符运算符（如==，!=，<=，:=）- 注释跳过：正确跳过单行或多行注释，不生成Token

## （2）最长匹配原则

当多个Token模式都能匹配当前位置的字符时，必须选择最长的匹配。例如：

- := 应识别为一个ASSIGN Token，而不是：和 = 两个 Token- == 应识别为一个 OP Token，而不是两个 = Token- ifx 应识别为标识符 ifx，而不是关键字 if + 标识符 x

## （3）错误检测与恢复

===== Page 4 =====

词法分析器必须能够检测并报告以下类型的错误：

| 错误类型 | 说明 | 示例 |
|----------|------|------|
| ILLEGAL_CHAR | 无法识别的字符 | $，@ |
| UNCLOSED_STRING | 未闭合的字符串字面量 | "hello |
| UNCLOSED_COMMENT | 未闭合的多行注释 | /* comment |
| INVALID_NUMBER | 格式错误的数字 | 3.14.15, 1e |

重要原则：遇到词法错误后，分析器应该跳过错误字符，继续分析后续内容，尽可能多地报告错误，而不是遇到第一个错误就停止。

## （4）位置信息

每个Token和每个错误都必须包含精确的行号和列号。行号从1开始计数，列号从每行第1个字符开始计数。Tab符视为1个字符宽度。

## 环节一：实验演示检查

环节一：实验演示检查- 学生现场演示（或提交完整录屏），展示编译器本阶段功能的完整运行流程，覆盖本实验全部必做功能。- 演示需同时体现：正常输入的正确处理，以及错误输入的检测与报告。- 助教可在演示过程中临时更换输入用例、要求你解释某段代码的作用或某个设计决策的理由。

## 环节二：AI协作过程记录检查

环节二：AI协作过程记录检查- 提交开发全过程中与智能体（Agent IDE / AI 助手，如 Claude Code、Cursor、CodeBuddy 等）的完整对话记录。- 记录需包含每一轮交互的三部分：(1) 你向智能体提出的问题或指令；(2) 智能体对该轮对话的完整响应；(3) 该轮的工作纪要——你做了什么决策、为什么这样做、如何验证结果。- 工作纪要不要求包含代码输出本身，重点是设计思路、决策理由与验证过程。- 课程鼓励使用 AI 工具，但你必须能够独立解释每一行代码与每一个设计选择。完整、连贯的对话记录是你真正参与开发的证据。
