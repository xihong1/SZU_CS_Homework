# 设计决策记录（NovaLang）

## 1. 结构语法选择：缩进块替代分号与大括号

- 决策：采用冒号加缩进表示块结构，不使用分号与花括号。
- 原因：语法噪声更少，程序层级更直观；对递归下降分析更友好。
- 备选：沿用 C/C++ 的分号加大括号。
- 否决理由：视觉负担较重，且与本语言“极简结构”目标不一致。

## 2. 安全提醒机制：使用阶段强制 @类型

- 决策：变量声明为 int a、string b；变量每次使用必须写成 a@int、b@string。
- 原因：把类型检查从声明时刻扩展到使用时刻，提升错误定位的可观测性。
- 备选：仅在声明时记录类型，使用时不附加后缀。
- 否决理由：读代码时类型上下文易丢失，不利于教学与自动化检查。

## 3. 类型转换策略：禁止强转，统一对象方法

- 决策：禁止 (float)x 这类 C 风格强转，仅允许 x@int.toFloat()、y@float.toInt()。
- 原因：转换语义单一且显式，可在语义阶段形成稳定规则。
- 备选：允许显式强转和方法转换并存。
- 否决理由：两套机制并存会增加歧义与实现复杂度。

## 4. 函数定义与调用统一箭头风格

- 决策：函数定义为 fn(返回类型) 函数名 -> 参数列表:；函数调用为 函数名->(参数列表)。
- 原因：定义与调用共享箭头视觉符号，便于初学者建立统一心智模型。
- 备选：采用传统函数调用语法 f(x)。
- 否决理由：与本语言“显式链路风格”不一致，辨识度不足。

## 5. 数组语法双形态

- 决策：保留 C 风格声明 int a[5]；元素访问写作 a[1]@int；整体引用写作 a@int[5]。
- 原因：同时满足声明直觉、元素类型提示和参数传递语义。
- 备选：只保留单一数组表示方式。
- 否决理由：无法同时覆盖元素访问与整体传递两种教学重点。

## 6. 运算符体系沿用 C++

- 决策：算术、关系、逻辑运算符集合完全对齐 C++。
- 原因：迁移成本低，教学重点可放在语法与语义实现。
- 备选：自定义关键字运算符或函数式运算符。
- 否决理由：提升学习与实现负担，不利于实验节奏。

## 7. 错误样例策略

- 决策：S6 固定提供词法、语法、语义三类错误样例。
- 原因：可以覆盖编译器前中期关键错误路径，支持答辩演示与回归测试。
- 备选：只提供混合错误样例。
- 否决理由：诊断维度不清晰，不利于验证错误分类准确性。

## 8. 主函数约束

- 决策：程序入口必须存在且仅接受 fn(void) main ->: 这一形式。
- 原因：入口规则固定，便于自动评测与后续代码生成阶段的统一入口映射。
- 备选：允许任意函数名或参数化 main。
- 否决理由：会增加评测和运行时装配复杂度。
