### 1.1 符号表与嵌套作用域管理

采用了基于**作用域栈**（Scope Stack）的嵌套符号表设计，将作用域分为三级：全局作用域（函数声明）→ 函数作用域（参数+局部变量）→ 块作用域（if/while块内变量）。核心数据结构由三个类组成：Symbol（符号表条目）、Scope（单个作用域）、SymbolTable（嵌套作用域符号表）。

具体代码实现如下：

```python
class Symbol:
    """符号表条目 — 记录变量/函数/参数/数组的完整信息"""
    def __init__(self, name, sym_type, kind, line, col, scope_level,
                 params=None, return_type=None, array_size=None):
        self.name = name              # 符号名称，如 "x", "fib"
        self.sym_type = sym_type      # 类型字符串，如 "int", "int[5]", "int(int,int)"
        self.kind = kind              # 实体种类: 'var' | 'param' | 'func' | 'array'
        self.line = line              # 声明行号（1-based）
        self.col = col                # 声明列号
        self.scope_level = scope_level # 作用域层级: 0=global, 1=function, 2+=block
        self.params = params or []    # 函数参数列表 [(name, type), ...]
        self.return_type = return_type # 函数返回类型
        self.array_size = array_size  # 数组大小（仅kind='array'时有值）
```

```python
class Scope:
    """单个作用域 — 维护该作用域中声明的所有符号"""
    def __init__(self, level=0):
        self.symbols = {}    # name -> Symbol 的映射字典
        self.level = level   # 该作用域的嵌套层级

    def define(self, symbol):
        self.symbols[symbol.name] = symbol

    def lookup(self, name):
        return self.symbols.get(name)    # 仅在当前作用域查找

    def contains(self, name):
        return name in self.symbols
```

```python
class SymbolTable:
    """嵌套作用域符号表 — 作用域栈 + 全局符号记录"""
    def __init__(self):
        self.scopes = []          # 作用域栈，scopes[-1]是当前（最内层）作用域
        self.all_symbols = []     # 所有已定义符号的列表（仅用于最终输出，不参与查找）

    def enter_scope(self):
        """进入新作用域（创建新Scope并入栈）"""
        level = len(self.scopes)
        self.scopes.append(Scope(level))

    def exit_scope(self):
        """退出当前作用域（栈顶出栈，该作用域中的符号不再可见）"""
        if self.scopes:
            self.scopes.pop()

    def lookup(self, name):
        """从内到外查找符号 — 这是实现变量遮蔽的关键
           从栈顶（最内层）向栈底（最外层）搜索，返回第一个匹配的符号
        """
        for scope in reversed(self.scopes):
            sym = scope.lookup(name)
            if sym is not None:
                return sym
        return None  # 所有作用域都找不到 → 未声明

    def lookup_current_scope(self, name):
        """仅在当前作用域查找 — 用于重复声明检测"""
        scope = self.scopes[-1]
        return scope.lookup(name)
```

对于嵌套作用域处理，设计要点如下：

**1）作用域的进入与退出**：在AST遍历过程中，遇到函数体时调用 `enter_scope()` 进入函数作用域；遇到if/while语句块时再次调用 `enter_scope()` 进入块作用域；离开时调用 `exit_scope()` 销毁当前作用域。作用域栈的变化与AST的递归遍历天然对应。

**2）变量遮蔽**：`lookup()` 方法从栈顶向栈底搜索，内层同名变量会被优先找到，天然实现了变量遮蔽。以S2场景中三个嵌套的 `value` 变量为例——最内层的 `value`（scope_level=3）会遮蔽外层的两个同名变量，每次使用时查找的都是当前作用域可见的最近声明。

**3）重复声明检测**：`lookup_current_scope()` 仅查找当前作用域，不穿透到外层。在变量或函数声明时调用此方法，若发现同名符号则报告 REDECLARED 错误。这确保了同一作用域内禁止重复声明，但不同作用域允许同名。

**4）两遍分析策略**：为支持函数间的相互调用和前向引用（如fib递归），语义分析采用两遍遍历。第一遍 `_declare_function()` 遍历所有FuncDecl节点，只记录函数签名到全局符号表；第二遍 `_check_function()` 再次遍历，在完整的函数签名表基础上逐一检查函数体。这类似于C语言的前向声明机制。

具体代码实现如下：

```python
def check(self, ast):
    """入口：对整个AST进行语义检查——实现两遍分析"""
    self.errors = []
    self.symtab = SymbolTable()
    self.symtab.enter_scope()      # 进入全局作用域
    self._register_builtins()      # 注册内置函数（如print）

    # ========== 第一遍：收集所有函数声明 ==========
    funcs = ast.get("funcs", [])
    for func in funcs:
        if func.get("type") == "FuncDecl":
            self._declare_function(func)   # 只记录签名，不检查函数体

    # ========== 第二遍：检查每个函数体 ==========
    for func in funcs:
        if func.get("type") == "FuncDecl":
            self._check_function(func)     # 进入函数作用域，检查全部语句

    self.symtab.exit_scope()
    symbols_out = [sym.to_dict() for sym in self.symtab.all_symbols]
    return {"errors": [e.to_dict() for e in self.errors], "symbols": symbols_out}
```

### 1.2 类型检查系统的实现

NovaLang采用**静态强类型**系统，所有变量类型在编译时确定。类型检查的核心是表达式类型推导——`_check_expr()` 作为总入口，根据AST节点类型分发到对应的专用检查方法，每个方法递归检查子表达式并返回该节点的类型字符串。

表达式类型推导的完整分发链如下：

```python
def _check_expr(self, node):
    """表达式检查的总入口——返回表达式的类型字符串；出错时返回None
       这是类型推导的核心：从叶子向上递归计算每个子表达式的类型
    """
    if node is None:
        return None
    node_type = node.get("type", "")

    # 字面量：类型直接确定，无需查表
    if node_type == "IntLiteral":       return "int"
    elif node_type == "FloatLiteral":   return "float"
    elif node_type == "StringLiteral":  return "string"
    elif node_type == "BoolLiteral":    return "bool"

    # 标识符/引用：需要查符号表
    elif node_type == "Identifier":
        return self._check_identifier(node)       # 普通标识符 → 查符号表
    elif node_type == "TypedVarRef":
        return self._check_typed_var_ref(node)    # a@int → 交叉验证+返回类型
    elif node_type == "TypedArrayRef":
        return self._check_typed_array_ref(node)  # a@int[5] → 数组整体
    elif node_type == "TypedArrayElemRef":
        return self._check_typed_array_elem_ref(node) # a[0]@int → 数组元素

    # 复合表达式：递归检查子表达式，综合计算类型
    elif node_type == "BinaryExpr":
        return self._check_binary_expr(node)      # 二元运算
    elif node_type == "UnaryExpr":
        return self._check_unary_expr(node)       # 一元运算
    elif node_type == "CallExpr":
        return self._check_call_expr(node)        # 函数调用
    elif node_type == "MethodCall":
        return self._check_method_call(node)      # 方法调用（toFloat/toInt）
    elif node_type == "MemberAccess":
        return self._check_member_access(node)    # 成员访问
    else:
        return None
```

**运算符类型约束**：NovaLang将二元运算符分为四类，每类有不同的类型约束：

| 运算符类别 | 运算符 | 操作数类型要求 | 结果类型 |
|-----------|--------|---------------|---------|
| 算术运算 | + - * / | int 或 float（左右类型一致） | 与操作数相同 |
| 算术(取模) | % | int（左右类型一致） | int |
| 关系运算 | < <= > >= | int 或 float（左右类型一致） | bool |
| 相等运算 | == != | int/float/string/bool（左右类型一致） | bool |
| 逻辑运算 | && \|\| | bool（左右类型一致） | bool |

二元表达式检查的代码实现：

```python
def _check_binary_expr(self, node):
    """检查二元表达式 — 运算符类型约束验证"""
    op = node.get("op", "")
    left, right = node.get("left"), node.get("right")
    line, col = node.get("line", 0), node.get("col", 0)

    # 1. 递归获得左右操作数类型
    left_type = self._check_expr(left)
    right_type = self._check_expr(right)
    if left_type is None or right_type is None:
        return None

    # 2. 验证左右类型一致性（NovaLang所有二元运算符都要求左右同类型）
    if left_type != right_type:
        self.error("TYPE_MISMATCH",
                   f"operator '{op}' requires operands of same type, "
                   f"got '{left_type}' and '{right_type}'",
                   line, col, expected=left_type, found=right_type)
        return left_type  # 容错：以左类型为准继续分析

    # 3. 按运算符类别进行类型约束检查
    if op in ARITHMETIC_OPS:          # + - * / %
        if left_type not in VALID_ARITHMETIC_TYPES:
            self.error("TYPE_MISMATCH",
                       f"arithmetic operator '{op}' requires numeric type, "
                       f"got '{left_type}'", line, col,
                       expected="int or float", found=left_type)
        if op == "%" and left_type != "int":
            self.error("TYPE_MISMATCH",
                       f"modulo operator '%' requires 'int', got '{left_type}'",
                       line, col, expected="int", found=left_type)
        return left_type

    elif op in RELATIONAL_OPS:        # < <= > >=
        if left_type not in VALID_RELATIONAL_TYPES:
            self.error("TYPE_MISMATCH", ...)
        return "bool"                 # 关系运算结果总是bool

    elif op in EQUALITY_OPS:          # == !=
        return "bool"                 # 相等运算结果总是bool

    elif op in LOGICAL_OPS:           # && ||
        if left_type != "bool":
            self.error("TYPE_MISMATCH", ...)
        return "bool"
```

**类型兼容规则**：NovaLang采用严格类型匹配原则，不允许隐式类型转换。int与float即使都是数值类型也不兼容。类型转换必须通过显式方法调用：`x@int.toFloat()` 将int转float，`x@float.toInt()` 将float转int。

方法调用的类型检查：

```python
def _check_method_call(self, node):
    """检查方法调用: object.method(args)
       NovaLang内置方法: toFloat()[只能在int上调用], toInt()[只能在float上调用]
    """
    obj = node.get("object")      # 方法调用的接收者
    method = node.get("method", "")

    obj_type = self._check_expr(obj)  # 先推导接收者类型

    if method == "toFloat":
        if obj_type is not None and obj_type != "int":
            self.error("TYPE_MISMATCH",
                       f"'toFloat()' can only be called on 'int', got '{obj_type}'",
                       line, col, expected="int", found=obj_type)
        return "float"             # toFloat() 返回 float

    elif method == "toInt":
        if obj_type is not None and obj_type != "float":
            self.error("TYPE_MISMATCH",
                       f"'toInt()' can only be called on 'float', got '{obj_type}'",
                       line, col, expected="float", found=obj_type)
        return "int"               # toInt() 返回 int

    else:
        self.error("UNDECLARED", f"unknown method '{method}'", ...)
        return None
```

**@类型注解交叉验证**：NovaLang要求变量使用时必须标注@类型（如 `a@int`）。`_check_typed_var_ref()` 方法不仅查找变量是否已声明，还验证使用时标注的类型是否与声明时一致——声明类型与使用类型必须完全匹配。这种"双重检查"机制是NovaLang"类型透明"设计哲学的核心体现。

```python
def _check_typed_var_ref(self, node):
    """检查带类型引用: name@Type — 交叉验证声明类型 == 使用标注类型"""
    name = node.get("name", ""); ref_type = node.get("ref_type", "")
    sym = self.symtab.lookup(name)
    if sym is None:
        self.error("UNDECLARED", f"'{name}' is not declared", ...)
        return ref_type  # 容错: 返回标注类型以便继续分析
    if sym.kind == "func":
        self.error("TYPE_MISMATCH", f"'{name}' is a function, not a variable", ...)
        return ref_type
    # ★ 交叉验证: 声明的类型必须与使用的@类型一致
    if sym.sym_type != ref_type:
        self.error("TYPE_MISMATCH",
                   f"'{name}' declared as '{sym.sym_type}', used as '{ref_type}'", ...)
    return ref_type
```

### 1.3 语义错误检测与定位

实现了严格的语义错误检测机制，覆盖7种基本错误类型和1种扩展错误类型。错误信息包含精确的行号和列号，通过 `SemanticError` 类进行结构化记录：

```python
class SemanticError(Exception):
    """语义错误 — 继承自Exception但不抛出，仅用于结构化记录"""
    def __init__(self, error_type, message, line, col, **extra):
        self.error_type = error_type   # 错误类型标识符
        self.message = message         # 人类可读的描述
        self.line = line               # 精确行号
        self.col = col                 # 精确列号
        self.extra = extra             # 额外上下文 {symbol, expected, found, ...}

    def to_dict(self):
        """序列化为JSON兼容格式"""
        d = {"type": self.error_type, "line": self.line, "col": self.col}
        d.update(self.extra)
        return d

def error(self, error_type, message, line, col, **extra):
    """记录一个语义错误（不中断分析）"""
    err = SemanticError(error_type, message, line, col, **extra)
    self.errors.append(err)  # 追加到错误列表，继续分析后续节点
```

各错误类型的检测时机和检测方法：

| 错误类型 | 检测时机 | 检测方法 | 示例 |
|----------|---------|---------|------|
| UNDECLARED | 使用变量/函数时 | symtab.lookup()返回None | y@int = 1（y未声明） |
| REDECLARED | 声明变量/函数时 | lookup_current_scope()已有同名符号 | int x; int x; |
| TYPE_MISMATCH | 赋值/运算/条件时 | 比较左右类型或检查运算符合法性 | int a = "hello" |
| RETURN_TYPE_MISMATCH | return语句 | 比较返回表达式类型与函数声明 | fn(int)→: return "s" |
| ARG_COUNT_MISMATCH | 函数调用时 | len(args) != len(params) | f(1)但f需要2参数 |
| ARG_TYPE_MISMATCH | 函数调用时 | 逐参数比较类型 | f("s")但形参为int |
| NOT_A_FUNCTION | ->调用时 | 被调用者kind ≠ "func" | x->(1,2)但x是变量 |

以函数调用检查为例，一次调用中可能同时触发多种错误：

```python
def _check_call_expr(self, node):
    """检查函数调用: callee->(arg1, arg2, ...)
       返回被调用函数的返回类型
    """
    callee = node.get("callee", {}); args = node.get("args", [])
    callee_name = callee.get("name", "")

    # 步骤1: 从符号表查找被调用函数
    sym = self.symtab.lookup(callee_name)
    if sym is None:
        self.error("UNDECLARED",                     # ★ 未声明
                   f"function '{callee_name}' is not declared", ...)
        return None

    # 步骤2: 验证被调用者确实是函数
    if sym.kind != "func":
        self.error("NOT_A_FUNCTION",                 # ★ 非函数调用
                   f"'{callee_name}' is not a function", ...)
        return None

    # 步骤3: 检查实参个数与形参个数是否一致
    expected_params = sym.params
    if len(args) != len(expected_params):
        self.error("ARG_COUNT_MISMATCH",             # ★ 参数个数错误
                   f"function '{callee_name}' expects "
                   f"{len(expected_params)} arguments, got {len(args)}", ...)

    # 步骤4: 逐个检查实参类型与对应形参类型是否匹配
    for i, arg in enumerate(args):
        arg_type = self._check_expr(arg)             # 递归推导实参类型
        if arg_type is not None and i < len(expected_params):
            expected_type = expected_params[i][1]
            if expected_type == "any":               # 内置函数（如print）接受任意类型
                continue
            if arg_type != expected_type:
                self.error("ARG_TYPE_MISMATCH",      # ★ 参数类型错误
                           f"argument {i+1} of '{callee_name}' expects "
                           f"'{expected_type}', got '{arg_type}'", ...)

    return sym.return_type  # 返回函数的返回类型
```

### 1.4 语义错误恢复——"继续分析"策略

为了在一次运行中报告尽可能多的语义错误，而不是遇到第一个错误就停止，我实现了**"检测-记录-继续"**模式。与实验三的恐慌模式（panic-mode）不同，语义分析阶段的AST结构是完整的，不需要跳过token，而是在每个AST节点上验证语义规则，发现错误时调用 `self.error()` 记录错误信息，然后继续遍历后续节点。

具体的容错机制包括三个方面：

**1）类型推导容错**：当子表达式类型推导出错时返回 `None`，父节点检测到 `None` 后跳过依赖该类型的后续检查，但不会中断整个分析。

**2）符号查找容错**：当变量未声明时（`lookup()` 返回 `None`），TypedVarRef的检查方法不直接终止，而是返回注解中标注的类型（如 `a@int` 中的 `"int"`）作为容错类型，使得涉及该变量的外層表达式仍然可以被部分检查。

**3）重复声明容错**：当检测到重复声明时，调用 `return` 跳过该符号的注册（避免覆盖已有的正确符号），但不会阻止后续代码的分析。

以S8场景中的8个语义错误为例，所有错误均能在一次运行中被全部捕获：

```json
{
  "errors": [
    {"type": "UNDECLARED",           "symbol": "y",   "line": 7,  "col": 13},
    {"type": "REDECLARED",           "symbol": "x",   "line": 12, "col": 5},
    {"type": "TYPE_MISMATCH",        "expected": "int", "found": "string", "line": 19, "col": 5},
    {"type": "RETURN_TYPE_MISMATCH", "expected": "int", "found": "string", "line": 25, "col": 5},
    {"type": "ARG_COUNT_MISMATCH",   "symbol": "add", "expected": "2", "found": "1", "line": 33, "col": 13},
    {"type": "ARG_TYPE_MISMATCH",    "symbol": "add", "expected": "int", "found": "string", "line": 40, "col": 13},
    {"type": "NOT_A_FUNCTION",       "symbol": "x",   "line": 46, "col": 13},
    {"type": "TYPE_MISMATCH",        "expected": "int", "found": "bool", "line": 54, "col": 13}
  ]
}
```

这验证了"继续分析"策略的有效性——前一个错误（第7行的UNDECLARED）不会阻止后续错误（第12行的REDECLARED、第19行的TYPE_MISMATCH等）的检测和报告。

### 1.5 分析方法

采用的是基于AST遍历的**访问者模式**（Visitor Pattern）。_check_statement()作为语句检查的入口，根据AST节点的type字段将检查任务分发到对应的专用检查方法：

```python
def _check_statement(self, node):
    """语句检查的分发器——根据节点类型路由到对应方法"""
    if node is None:
        return
    node_type = node.get("type", "")

    if node_type == "VarDecl":
        self._check_var_decl(node)          # 变量声明检查
    elif node_type == "AutoVarDecl":        # ★ auto类型推导（选做）
        self._check_auto_decl(node)
    elif node_type == "AssignStmt":
        self._check_assign(node)            # 赋值语句检查
    elif node_type == "IfStmt":
        self._check_if(node)                # if语句（含作用域进入/退出）
    elif node_type == "WhileStmt":
        self._check_while(node)             # while语句（含作用域进入/退出）
    elif node_type == "ReturnStmt":
        self._check_return(node)            # return语句（含返回类型匹配）
    elif node_type == "ExprStmt":
        self._check_expr(node.get("expr"))  # 表达式语句（仅推导类型）
    elif node_type == "BreakStmt":
        pass  # break语句无语义检查需求
    elif node_type == "ContinueStmt":
        pass  # continue语句无语义检查需求
```

选择访问者模式而非属性文法的理由：1）Python语言中访问者模式通过if-elif分发结构更自然地映射，代码可读性高；2）与实验三的递归下降解析器风格一致，形成统一的代码组织模式；3）每种AST节点对应一个检查方法，职责单一，扩展新节点类型只需添加一个方法和一个case分支，不修改现有逻辑。

此外，表达式检查采用**递归类型推导**模式。_check_expr()方法的返回值是该表达式的类型字符串（如"int"、"bool"等），叶子节点（字面量）直接返回基本类型，内部节点（二元运算、函数调用等）通过递归获取子表达式类型后综合计算。这种自底向上的类型传播机制天然适合表达式树的语义分析。

### 1.6 选做：auto类型推导

作为选做加分内容，实现了基于 `auto` 关键字的局部变量类型推导。auto关键字允许省略显式类型声明，编译器根据初始化表达式自动推断变量类型。实现需要同时在**词法层、语法层和语义层**进行修改：

**词法层**：在 TOKEN_SPECS 的 KEYWORD 正则中添加 `auto`：

```python
# 修改前:
('KEYWORD', r'\b(fn|void|int|float|string|bool|return|break|...)\b')
# 修改后:
('KEYWORD', r'\b(fn|void|int|float|string|bool|auto|return|break|...)\b')
```

**语法层**：在 Parser 类中，将 auto 加入语句起始关键字集合（is_stmt_start），在 parse_statement 中添加分发到新增的 parse_auto_decl() 方法：

```python
def parse_auto_decl(self):
    """解析 auto 类型推导声明: auto name = expr"""
    auto_tok = self.advance()           # 消费 'auto'
    name_tok = self.expect("ID")        # 变量名
    self.expect("OP", "=")              # 等号（auto声明必须有初始化表达式）
    init = self.parse_expr()            # 解析初始化表达式
    return {
        "type": "AutoVarDecl",          # 新的AST节点类型
        "name": name_tok["value"],
        "init": init,
        "line": auto_tok["line"],
        "col": auto_tok["col"],
    }
```

**语义层**：新增 _check_auto_decl() 方法，核心逻辑是从初始化表达式推导类型——调用 `_check_expr(init)` 递归获取表达式类型，将其作为变量的声明类型存入符号表：

```python
def _check_auto_decl(self, node):
    name = node.get("name", ""); init = node.get("init")
    if self.symtab.lookup_current_scope(name):
        self.error("REDECLARED", f"'{name}' is already declared", ...)
        return
    inferred_type = self._check_expr(init) or "int"
    sym = Symbol(name, inferred_type, "var",
                 line, col, self.symtab.current_level())
    self.symtab.define(sym)
```

关键设计：推导出的类型直接作为 sym_type 存入符号表，后续该变量通过 @类型注解使用时（如 `a@int`），检查逻辑与普通声明变量完全一致——都是比较注解类型与符号表中存储的推导类型。这使得 auto 功能与现有类型系统无缝集成，无需任何特殊处理。

## 4. 设计与实现说明

### 4.1 你的语言的类型系统是怎样的？有哪些类型？类型兼容规则是什么？

NovaLang的类型系统采用**静态强类型**设计，所有类型在编译时确定。

**基本类型**：int（整型）、float（浮点型）、string（字符串）、bool（布尔型）、void（空类型，仅用于函数返回值）。

**复合类型**：数组类型（如 `int[5]`）、函数类型（在符号表中表示为 `int(int,int)` 等形式）。

**类型兼容规则——严格匹配原则**：NovaLang不允许隐式类型转换。int与float不兼容，string与数值类型不兼容，bool与其他类型不兼容。所有类型转换必须通过显式方法调用：
- `x@int.toFloat()` → int转float
- `x@float.toInt()` → float转int

**运算符类型规则**：算术运算（+、-、*、/）要求int或float，%（取模）仅int；关系运算（<、<=、>、>=）要求int或float，结果为bool；相等运算（==、!=）可用于int/float/string/bool，结果为bool；逻辑运算（&&、||、!）要求bool。

**函数调用规则**：实参与形参个数相同、类型一一对应。内置函数print的参数类型为"any"，跳过类型检查。

| 类型 | 关键字 | 字面量示例 | 说明 |
|------|--------|-----------|------|
| 整型 | int | 42, 0, -7 | 整数 |
| 浮点型 | float | 3.14, 2.0 | 浮点数 |
| 字符串 | string | "hello" | 字符串字面量，支持转义 |
| 布尔型 | bool | true, false | 布尔值，逻辑运算的操作数 |
| 空类型 | void | 无 | 仅用于函数返回类型 |

### 4.2 符号表与作用域是如何实现的？如何处理嵌套作用域与变量遮蔽？

符号表采用**作用域栈**（Scope Stack）结构。核心由三个类组成：
- **Symbol**：记录名称、类型字符串、种类（var/param/func/array）、声明位置（line/col）、作用域层级
- **Scope**：单个作用域，内部维护 `name → Symbol` 字典
- **SymbolTable**：管理 `scopes` 列表（栈），提供 enter/exit/define/lookup/lookup_current_scope 方法

**嵌套作用域处理**：在AST遍历过程中，遇到函数体、if语句块、while语句块时分别调用 `enter_scope()` 创建新Scope并入栈；离开时调用 `exit_scope()` 出栈销毁。

**变量遮蔽**：`lookup()` 从栈顶（最内层）向栈底（最外层）搜索，返回第一个匹配的符号。内层同名变量会被优先找到，天然实现了变量遮蔽。以S2场景中的三个嵌套value变量为例：最内层value（scope_level=3）遮蔽中间层value（scope_level=2），中间层遮蔽外层value（scope_level=1）。每次使用时查找的都是当前作用域可见的最近声明。

**重复声明检测**：`lookup_current_scope()` 仅查找当前作用域（不穿透到外层）。声明变量/函数时调用此方法，若发现同名符号则报告REDECLARED错误。确保同一作用域内禁止重名，但不同作用域允许同名（即合法的变量遮蔽）。

### 4.3 类型检查是如何在AST上进行的（属性文法/访问者模式）？

采用**访问者模式 + 递归类型推导**。核心设计：

**_check_statement()** 作为语句检查的分发器，根据 AST 节点的 `type` 字段路由到对应的检查方法（_check_var_decl、_check_assign、_check_if、_check_while、_check_return 等）。每种语句结构的语义规则封装在各自的检查方法中。

**_check_expr()** 作为表达式检查的总入口，返回该表达式的**类型字符串**。叶子节点（字面量）直接返回类型；标识符节点查符号表返回类型；复合表达式节点递归获取子表达式类型后综合计算。

**递归类型推导的核心优势**：每个检查方法只需关注当前节点类型的规则，子表达式的类型由递归调用自动获得。以 `a@int + b@int` 为例：
1. `_check_expr(a@int)` → `_check_typed_var_ref()` → 查符号表 → 验证 `@int` 与声明类型一致 → 返回 `"int"`
2. `_check_expr(b@int)` → 同理返回 `"int"`
3. `_check_binary_expr()` → 验证左右类型一致 → 验证 `+` 对 `int` 合法 → 返回 `"int"`

### 4.4 语义错误的检测策略是什么？举例说明。

检测策略采用**"检测-记录-继续"**模式。发现语义错误时不抛出异常中断分析，而是调用 `self.error()` 将错误信息追加到 `self.errors` 列表，然后继续遍历AST的后续节点。

**容错机制**：
1. 类型推导出错时返回 `None`，父节点检查到 `None` 后跳过依赖检查
2. 变量未声明时，返回注解中的类型（如 `a@int` 的 `"int"`）作为容错类型，使得外層表达式可继续被部分检查
3. 重复声明时跳过符号注册（不覆盖已有正确符号），但不阻止后续代码分析

**多错误示例**：S8场景中8个错误（UNDECLARED、REDECLARED、TYPE_MISMATCH×2、RETURN_TYPE_MISMATCH、ARG_COUNT_MISMATCH、ARG_TYPE_MISMATCH、NOT_A_FUNCTION）均在一次运行中被全部捕获。前一个错误不阻止后续错误的检测——第7行的未声明错误不会影响第12行重复声明错误的检测，第19行的赋值类型错误不会影响第25行返回类型错误的检测。这比传统的"遇第一个错误就停止"的模式显著提升了调试效率。

### 4.5 语义分析器如何与语法分析（实验三）、中间代码生成（实验五）对接。

**与语法分析（实验三）的对接**：

语法分析器输出 `{"ast": {...}, "errors": [...]}` 字典。语义分析器直接接收AST作为输入，接口约定是AST根节点为Program类型（包含funcs列表）。在compiler.py的check命令中，先运行词法+语法分析，若存在前端错误则跳过语义分析（因为AST可能不完整），直接输出前端错误；仅在无前端错误时才调用semantic_module.semantic_check(ast)进行语义分析。

```python
# compiler.py check 命令的对接逻辑
if all_frontend_errors:
    # 词法/语法有错误，跳过语义分析
    output_json({"errors": all_frontend_errors, "symbols": []})
else:
    from semantic_module import semantic_check
    result = semantic_check(ast)
    output_json(result)
```

**与代码生成（实验五）的预留对接**：

1）**符号表**：语义分析器输出的symbols列表记录了所有变量和函数的类型、作用域、声明位置。代码生成阶段可直接查询符号表获取变量的内存分配信息（类型→字节数）和函数的签名信息（参数个数/类型→栈帧布局）。

2）**类型信息**：每个变量和表达式的类型已在语义分析阶段确定，代码生成阶段无需再做类型推断，可直接根据类型选择对应的指令（如int用IADD、float用FADD）。

3）**语义错误保障**：语义错误列表确保只有语义正确的程序才进入代码生成阶段，避免了在代码生成时才发现类型错误的低效情况。

4）**函数类型字符串**（如 `"int(int,int)"`）可直接用于生成函数调用时的参数压栈和返回值处理代码。
