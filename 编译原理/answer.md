# 实验一答辩问题回答

## 1. Chomsky 四型文法的定义、判定方法与区别

### 1.1 0 型文法（Type-0，无限制文法）

定义：
1. 产生式一般写作 α -> β。
2. α、β 都是由终结符和非终结符构成的串，且 α 至少包含一个非终结符。
3. 对产生式形态几乎不做限制。

判定方法：
1. 若文法不满足 1/2/3 型条件，但仍是合法产生式系统，则属于 0 型。
2. 实际判定通常按“从严到宽”进行：先试 3 型，再试 2 型，再试 1 型，最后归为 0 型。

示例：
1. S -> SA
2. SA -> A
3. A -> a
该文法存在长度缩短且不满足 1 型约束的规则，因此归 0 型。

### 1.2 1 型文法（Type-1，上下文相关文法）

定义：
1. 所有产生式满足 |左部| <= |右部|。
2. 允许唯一特例 S -> ε，但要求 S 不出现在任何产生式右部。

判定方法：
1. 检查每条产生式是否满足长度不减。
2. 若有违反长度不减规则的产生式，则不是 1 型。
3. 若全部满足且不属于更严格的 2/3 型，则判为 1 型。

示例：
1. S -> AB
2. AB -> BA
3. A -> a
4. B -> b
其中 AB -> BA 左右长度相同，满足 1 型条件。

### 1.3 2 型文法（Type-2，上下文无关文法）

定义：
1. 每条产生式左部必须是单个非终结符。
2. 右部可以是任意符号串。

判定方法：
1. 遍历产生式，检查左部是否全部是单个非终结符。
2. 若成立且不是 3 型，则判为 2 型。

示例：
1. S -> aSb | ε
左部始终是单一非终结符 S，因此是 2 型。

### 1.4 3 型文法（Type-3，正则文法）

定义：
1. 右线性：A -> aB 或 A -> a 或 A -> ε。
2. 左线性：A -> Ba 或 A -> a 或 A -> ε。
3. 左线性与右线性不可混用，混用应降级为 2 型。

判定方法：
1. 先检查是否满足 2 型前提（左部单非终结符）。
2. 再检查每条规则是否都符合右线性或都符合左线性。
3. 全部右线性输出 TYPE_3_RIGHT；全部左线性输出 TYPE_3_LEFT。

示例：
1. S -> aA | a
2. A -> bA | b
属于典型右线性文法。

### 1.5 四型文法的核心区别总结

1. 约束强弱：3 型最强，0 型最弱。
2. 左部限制：2/3 型要求左部单非终结符，1/0 型可更一般。
3. 长度约束：1 型要求长度不减，0 型无此要求。
4. 可识别语言能力：从 3 到 0 逐渐增强，但分析与实现复杂度也逐渐上升。

## 2. 文法分析器的判定算法实现与时间复杂度

### 2.1 总体流程（按当前实现）

结合 [src/main.cpp](src/main.cpp) 的实现，流程如下：

1. 解析输入文件：读取 N/T/P/START 四个区块，构建 Grammar 结构。
2. 合法性验证：
   - FORMAT_ERROR
   - START_NOT_IN_N
   - UNDEFINED_SYMBOL
   - UNREACHABLE
   - NON_GENERATING
3. 若 --check-type：
   - 有错误则输出 INVALID。
   - 无错误时按 3 -> 2 -> 1 -> 0 顺序判型。
4. 若 --stats：输出统计字段。
5. 若 --ambiguity-check：做有界搜索并输出 witness。

### 2.2 合法性验证算法细节

1. 未定义符号检查
遍历所有产生式左右符号，检查是否属于 N 或 T。

2. 可达性检查（UNREACHABLE）
从 START 做 BFS，只沿“左部为单非终结符”的规则扩展右部中的非终结符。

3. 可生成性检查（NON_GENERATING）
迭代不动点：
- 若 A -> rhs 且 rhs 由终结符或已可生成非终结符组成，则 A 可生成。
- 重复直到集合不再增长。

### 2.3 类型判定算法细节

1. 先判 2 型前提：所有左部是否单非终结符。
2. 在 2 型前提下：
   - 检查全部右线性规则。
   - 检查全部左线性规则。
3. 若两者都不满足但满足 2 型，输出 TYPE_2。
4. 若不满足 2 型，再按 1 型长度不减规则检查。
5. 仍不满足则归 TYPE_0。

### 2.4 时间复杂度分析

设：
1. P 为候选式总数（考虑 | 分裂后的规则数）。
2. L 为单条规则平均符号长度。
3. V 为非终结符数量。
4. E 为“可达性图”中的边数量近似（由规则右部非终结符贡献）。

主要阶段复杂度：

1. 解析阶段：O(P * L)
2. 未定义符号检查：O(P * L)
3. 可达性 BFS：O(V + E)
4. 可生成性不动点：最坏 O(V * P * L)
5. 类型判定：O(P * L)

因此主导项通常是可生成性迭代，整体可视为 O(V * P * L)。对课程规模输入通常足够快，满足实验的时限要求。

### 2.5 当前实现的工程特点与边界

1. 优点：结构清晰，判定顺序明确，便于调试与答辩解释。
2. 局限：UNREACHABLE/NON_GENERATING 的实现偏向“左部单非终结符”路径，对部分严格 1 型文法可能偏保守。
3. 二义性检测是有界搜索，不是不可判定问题上的完备判定，这在理论上是合理取舍。

## 3. 语言设计特点、设计动机与被否决方案

### 3.1 NovaLang 的核心特点

结合 [language_spec.md](language_spec.md) 与 [decisions.md](decisions.md)，核心特点如下：

1. 极简结构：用冒号和缩进定义块，去掉分号和花括号。
2. 显式严谨类型：先声明类型，使用时强制写 @类型。
3. 安全提醒机制：类型信息在每次使用时可见。
4. 万物皆对象：禁止 C 风格强转，只允许 .toFloat()/.toInt()。
5. 箭头调用统一：函数定义与调用都用 -> 形成统一视觉风格。
6. 数组双形态：a[i]@int 与 a@int[5] 分别表达元素与整体语义。
7. 运算符沿用 C++：降低学习迁移成本。

### 3.2 为什么这样设计

1. 教学目标导向：语法不能太复杂，但必须覆盖完整编译流程。
2. 可实现性导向：递归下降与缩进词法结合，工程实现路径清晰。
3. 可答辩性导向：@类型提醒机制有辨识度，便于解释创新点。
4. 可诊断性导向：语义错误更容易定位到使用位置而非仅声明位置。

### 3.3 被否决的备选方案

1. C/C++ 风格块结构（分号+大括号）
否决原因：语法噪声更高，与“极简结构”目标冲突。

2. 仅声明处记录类型，使用处不写后缀
否决原因：阅读时类型上下文容易丢失，不利于教学与自动检查。

3. 同时允许强转与方法转换
否决原因：语义规则分裂，增加歧义与实现复杂度。

4. 传统调用 f(x)
否决原因：与箭头风格不统一，语言辨识度不够。

5. 数组只保留一种引用写法
否决原因：难以同时表达“元素访问”与“整体传参”两种教学重点。

## 4. 如果重新设计，会做哪些改变

在保持核心哲学不变的前提下，下一版我会做以下改进：

1. 改进文法分析器对 1 型文法验证的策略
把可达性与可生成性算法扩展为“适配一般左部串”的版本，减少对 1 型文法的误拒绝，提升理论一致性。

2. 增加错误码体系与标准诊断格式
将词法、语法、语义错误统一到错误码规范，例如 LEX001/SYN002/SEM003，并固定输出结构，便于自动评测。

3. 增加语言规范中的形式化示例集
在设计文档中加入“合法/非法最小对照片段”，让评测与答辩时可以快速演示边界行为。

4. 细化数组与方法调用的类型规则
明确数组长度是否参与函数签名匹配、方法调用是否允许链式转换等细节，减少语义歧义。

5. 为后续实验预留中间表示接口
在语法树节点中加入类型注解、作用域编号和控制流标签，为三地址码生成与优化留足接口。

6. 增加自动化回归脚本
把 tests 下文法按预期结果做批量校验，覆盖 --check-type、--validate、--stats，避免手工回归遗漏。
