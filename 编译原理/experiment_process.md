# 实验过程与核心算法实现说明 (Experimental Process and Core Algorithm Feature Documentation)

## 一、 实验环境与整体架构设计

### 1.1 实验开发环境
- **开发语言**：C++17 (利用其结构化绑定、std::string_view、std::optional 等现代特性提升代码鲁棒性)。
- **编译环境**：GCC (MinGW-w64) / Clang，配合 GDB 及 Makefile 进行构建与调试。
- **运行平台**：Windows 11 (PowerShell/CMD) 与 Linux 双平台兼容。

### 1.2 总体架构说明
文法分析器（Grammar Analyzer）被设计为一个典型的“多趟（Multi-pass）”命令行程序。其核心处理管线（Pipeline）分为以下四个阶段：
1. **词法与预处理层（Lexical & Preprocessing）**：读取 .txt 文法定义文件，去除空白字符，并将输入文本切分为非终结符集 (N)、终结符集 (T)、产生式集 (P) 和起始符号 (S)。
2. **语法树/内部结构构建层（Internal Representation）**：将提取的字符串转化为核心数学模型数据结构 Grammar 和 Production。
3. **语义验证层（Semantic Validation）**：遍历内部数据结构，执行不可达符号、不可生成符号、未定义符号的图算法和集合求值算法验证。
4. **类型判定与二义性分析层（Classification & Ambiguity checking）**：在确保文法合法的前提下，基于乔姆斯基（Chomsky）文法体系的严格定义，层层判定文法类型；基于宽度优先广度搜索（BFS）算法进行二义性验证。

## 二、 核心数据结构设计

为了在 C++ 中高效且不失一般性地表示形式语言定义  = (N, \Sigma, P, S)$，设计了如下核心数据结构：

### 2.1 产生式结构 (Production)
产生式被定义为一个包含左部候选和右部候选的字符串序列。为了支持上下文有关文法（Type 1 文法）和无限制文法（Type 0 文法），产生式左部设计为 std::vector<std::string>，而不是单一字符串。这一设计彻底打破了仅能表示 CFG 的局限。
`cpp
struct Production {
    std::vector<std::string> lhs; // 产生式左部符号序列 (Left-hand side)
    std::vector<std::string> rhs; // 产生式右部符号序列 (Right-hand side)
    int lineNum;                  // 记录在输入文件中的行号，用于报错追踪
};
`

### 2.2 文法全局结构 (Grammar)
统一封装所有的文法数学要素，将其视为一个图（Graph）或逻辑实体，便于将其作为参数在不同算法模块间传递与遍历。
`cpp
struct Grammar {
    std::vector<std::string> nonTerminals; // 非终结符集合 N
    std::vector<std::string> terminals;    // 终结符集合 T
    std::vector<Production> productions;   // 产生式规则集合 P
    std::string startSymbol;               // 开始符号 S
};
`

## 三、 核心算法与实现细节

本实验的代码实现难点在于文法的逻辑合法性验证（尤其图可达性与不动点迭代）以及文法的乔姆斯基归类算法。

### 3.1 文法有效性验证算法 (Grammar Validation)
有效性验证独立于词法解析，作为第二趟扫描（Pass 2），必须查出以下四类核心语义错误：
- START_NOT_IN_N：起始符号未在非终结符集合中声明。
- UNDEFINED_SYMBOL：产生式中使用了既非终结符也非终结符的未声明符号。
- UNREACHABLE：存在从起始符号 $ 出发，无论经过多少步推导都无法达到的非终结符。
- NON_GENERATING：存在无法推导出任何纯终结符串的非终结符（即产生“死循环”或“死胡同”的符号）。

#### 3.1.1 连通性分析：不可达符号检测 (Unreachable Symbol Detection)
**算法描述**：将文法视为一个有向图（Directed Graph），其中非终结符为节点。如果存在产生式  \to \alpha B \beta$，则视为存在一条从节点 $ 到节点 $ 的有向边。不可达性验证即转化为求解从节点 $ 出发的可达分量问题。
**具体实现步骤**：
1. 初始化一个布尔哈希表 eachable，所有非终结符状态初始设为 alse。
2. 将起始符号 $ 标记为 	rue 并压入队列 Q。
3. 当队列 Q 不为空时循环：
   a. 弹出首部非终结符 $。
   b. 遍历所有左部包含 $ 的产生式（允许上下文有关注入）。
   c. 查找该产生式右部 (RHS) 的所有符号。如果是尚未访问的非终结符 $，则标记 eachable[X] = true 并压入队列 Q。
4. 队列遍历结束后，统计所有非终结符，若存在 eachable[X] == false，则抛出 UNREACHABLE 异常记录。

#### 3.1.2 活性分析：不可生成符号检测 (Non-generating Symbol Detection)
**算法描述**：采用自底向上的**不动点迭代算法 (Fixed-point Iteration)**。判定准则为：一个符号可生成，当且仅当它是终结符，或者它存在一个产生式，其右部所有元素都是已知的可生成符号。
**具体实现与伪代码**：
1. 初始化集合 generating，将所有终结符 $ 以及空字 $\epsilon$ 直接加入该核心集合。
2. 设置集合收敛标志位 changed = true。
3. while (changed == true):
   a. 重置 changed = false
   b. 依次遍历所有的产生式  : LHS \to RHS$。
   c. 若 $ 中有尚未加入 generating 的非终结符，且 $ 中的所有符号都已存在于 generating 中：
      - 将该 $ 中的非终结符加入 generating 集合。
      - 修改标识 changed = true，触发下一次全量迭代。
4. 迭代结束后（达到不动点），比对非终结符集 $：
   - 不在 generating 集合中的非终结符，触发 NON_GENERATING 错误报告。
*算法分析：该过程单次检测复杂度为 (|P|)$，最多膨胀扩展 $|N|$ 次即可收敛，时间上限为 (|N| \cdot |P|)$。*

### 3.2 乔姆斯基体系分类算法 (Chomsky Hierarchy Classification)
多道分派的最后一环，判定算法严格按照 Chomsky 体系的包容性子集关系，通过  3 \subset Type 2 \subset Type 1 \subset Type 0$ 的层级，**由最严苛到最宽松进行逆推判定**。

#### 3.2.1 3型文法（正则文法）判定
**理论基础**：
- 右线性文法 (Right-linear)：所有产生式形如  \to aB$ 或  \to a$ （其中 , B \in N, a \in \Sigma^*$）。
- 左线性文法 (Left-linear)：所有产生式形如  \to Ba$ 或  \to a$。
**实现规则**：
- 函数 isRightLinearRule 检测：
  - 如果右侧包含非终结符，它必须**且仅能有1个**，并且必须在句子的**绝对最右侧**。其他前置符号必须全是终结符。
- 函数 isLeftLinearRule 检测：
  - 包含非终结符时，必须位于**绝对最左侧**，其它同理。
- 综合评判：遍历全集 $。必须**所有**左线性产生式统一，或**所有**右线性产生式统一；若混用，判定立刻降级至 TYPE 2。

#### 3.2.2 2型文法（上下文无关文法 CFG）判定
**理论基础**：产生式特征为  \to \gamma$，其中左侧 $ 只能是单个固定的非终结符。
**实现规则**：
遍历 $，检查左侧符号串变量（LHS）长度。当 LHS.size() == 1 并且 LHS[0] 从属于非终结符表 $ 时，满足 TYPE 2 标准。

#### 3.2.3 1型文法（上下文有关文法 CSG）判定
**理论基础**：产生式呈现 $\alpha A \beta \to \alpha \gamma \beta$，通常体现为长度非递减限制 $|\alpha A \beta| \le |\alpha \gamma \beta|$。系统允许有一个特例： \to \epsilon$，但此时 $ 绝不能出现在任意右侧。
**实现规则**：
1. 先验查所有候选对是否满足 LHS.size() <= RHS.size()。
2. 特例审查：
   - 过滤处理右部为 $\epsilon$ 的例外。
   - 若出现  \to \epsilon$，激活 S_epsilon_rule_present 标识。然后深度遍历所有的右部，一旦发现 $ 在右侧做派生节点，立刻否决 1型判定。
若所有规则守住上述界限，输出 TYPE 1。

#### 3.2.4 0型文法（无限制文法）判定
**实现规则**：退化项截获。若前述分类全军覆没，只需检查产生式左部非空（LHS.size() > 0），并确保它并非只有无关终结符即可定为 TYPE 0。

### 3.3 二义性检测算法实现（实验加分机制）
为提升分析器的商用级能力，本程序实现了基于有界宽度优先搜索（Bounded BFS）与推导哈希计数的二义性诊断。该算法只对满足条件的 CFG 进行推演。

**算法运作步骤**：
1. **状态机表示**：定义广搜单元状态为 std::vector<std::string> current_sentence 并装载到 std::queue。
2. **初始化**：首个压入的状态仅含开始符号 $。
3. **层序扩展（有深度限制）**：
   - 每次从队列拉取一个句型表示。
   - 探测查找到第一个也是最左端的一个非终结符进行**最左推导**（Left-most Derivation），屏蔽多重排列干扰。
   - 用该变量所挂载的所有 $ 分支予以替换生成衍生向量并入队。
4. **终态捕捉与哈希查重**：
   - 直至队列弹出的句子完全由终结符拼凑时不再衍生，将其平铺序列化为 Key 值保存入哈希表 std::unordered_map<std::string, int>。
5. **碰撞告警**：
   - 每获取一个终结句就查表自增。一旦某个具象语句的推导技术 Value >= 2，中止所有线程，返回 mbiguous = true，并将原句子提取抛出为反例验证特征（Witness）。

## 五、 时间与空间复杂度深度分析

1. **主词法解析**：时间耗费 (C + |N| + |T|)$，其中 $ 属于原始文本常数量级字符。
2. **合法性约束**：
   - BFS 可达性图遍历：涉及顶点集 $|N|$ 和入度边集合，用邻接表最劣复杂度 (|N| + \sum |RHS|)$。
   - 不动点可生成矩阵迭代：单次 (|P|)$，至多扩散 $|N|$ 层，故时间封顶在 (|N| \cdot |P|)$。
3. **二义性检测**：暴力完全展开属于典型的 NP 范畴。设语法分支因子为 $，最长验证推导深度为 $，复杂度达到 (b^d)$。故而在参数中引入 --max-length 将其修剪为常量的多项式限界，避免因递归导致的内存溢出。
4. **总体量级与空间堆叠**：通过 C++ 高效封装，存储产生式仅划拨少许堆空间 (|P| \cdot L_{avg})$。整体内存生命周期控制优异，在课程万级字符测试下时间通常维系在 0.0x 秒内。

## 六、 实验具体实施操作步骤

为了将前述的理论概念和算法架构转化为实际的编译器前端系统，本实验的编码与功能验证按以下五个递进阶段（Development Phases）依次展开，这也是标准软件工程中常采用的迭代开发模型。

### 6.1 阶段一：前期环境准备与词法解析模块开发
本阶段完成了从读取纯文本到构建基础数据结构的转换。
1. **工程初始化与规范制定**：搭建 C++ 项目结构，配置 Makefile 与 GCC 编译参数（启用 -std=c++17 以支持较新的特性如结构化绑定）。
2. **基础切词工具库实现**：实现通用的字符串处理函数。例如去除首尾空白字符 (	rim)、按特定分隔符切分符号 (splitBySpace, splitByChar)。这是因为输入的文法定义文件可能存在多种排版习惯（存在多余空格或直接连写）。
3. **分群落解析器开发**：针对文法文件的四个固定段落（N:、T:、P:、START:），编写状态机逐段读取与前缀匹配逻辑；
   - 对产生式部分，设计算法兼容两种书写风格（松散有空格型如 A B 与紧凑型如 A）；
   - 在紧凑型解析时，应用“最长匹配原则”查验表内的非终结符变量，保障解析准确性。

### 6.2 阶段二：语义有效性验证模块开发（图算法落地）
此阶段保障了文法逻辑本身的无暇，不产生无效推导或死循环。
1. **符号有效性边界定义**：首先利用查找操作，判定 START 符号是否成功注册于 N 表；其次提取产生式中的每个切分单元，判别其是否游离于 N 和 T 集之外（抛出未定义异常）。
2. **可达性算法（图遍历）编码**：将非终结符转化为基于 std::unordered_map 的邻接表表示法。设置初始源点为 START，通过 std::queue 实现宽度优先搜索（BFS），把从 START 波及到的规则左部不断染色（标记查探）。遍历结束后统一清算未被染色的孤立节点。
3. **生成性算法（不动点）编码**：建立 generating 布尔哈希集，预先塞入所有的终结符 $ 与 $\epsilon$。通过一个粗粒度的 while(changed) 循环不断轮询所有规则 $。只要发现某条规则的右部全员“已确认为可生成”，就将其左侧标记为可生成，直至矩阵达到收敛不动点。

### 6.3 阶段三：乔姆斯基类型判定器开发
在明确文法合法后，从最受束缚的3型文法开始自底向上建立过滤筛。
1. **3型（正则）文法判定开发**：编写探测函数，针对右部遍历，根据非终结符出现的位置严格切分出“左线性检测仪”与“右线性检测仪”。在主干逻辑中统计二者状态，要求系统必须是“纯左”或“纯右”，任何混合情况立刻予以截断降级至2型。
2. **2型（CFG）文法判定开发**：增加简单的门限校验条件，即所有产生式左侧变量序列（LHS）长度唯一且从属于非终结符集。
3. **1型（CSG）文法与特例判定开发**：遍历校验序列长度的单调增生性 (|LHS| <= |RHS|)。并添加特例嗅探器：如果察觉  \to \epsilon$ 存在，就再加一把锁遍历所有 RHS，一旦发现 $ 在推导后文中做派生节点，立刻否决其1型身份。
4. **0型分配**：设计以上各卡口的 if-else 分支兜底机制，所有未能识别但至少左部不为空的，直接划定为0型。

### 6.4 阶段四：选做增强架构开发（二义性验证）
1. **控制流参数注册**：在命令入口增加 --ambiguity-check 标志和 --max-length 整型提取模块以便接收深度限制。
2. **最左推导生成器开发**：设立独立的广搜派生队列。利用规则“永远只向最早遇见的第一个非终结符展开替换”，这一策略可以屏蔽由于左右衍生次序不同导致的“假二义性”，确保只探究实质语法树结构的歧义。
3. **终端状态机与碰撞探针**：当推导序列仅存终结符时不再发散，将其转换格式送入全局哈希字典（Hash Table）查重。若某个句子的频次计步器 $\ge 2$，则立即冻结所有推导线程并捕获该句子串输出。

### 6.5 阶段五：系统总装集成与黑盒测试回归
1. **结构化输出接口封装**：将四重模块产生的警告（Error数组）、类别（Type）、二义性回溯串聚合入统合结构体 ParseResult。编写 printValidateJson 将其依据标准 JSON 格式树状打印排版（挂接字符转义功能）。
2. **边缘异常防护与回归测验**：调用全栈测试集（	ests/*.txt）。特意注入空文件、缺段落文件、死循环文件，排除了早期在找不到文件时发生的 SegFault 进程崩溃问题。以此为程序收口，保障在实验验收评测时的鲁棒性。

## 七、 实验综述分析
本项目围绕编译器前端技术中最富含算法基础的“文法分析”进行设计。由清晰模块化的内部数据结构发起，以严谨且可完备溯源的不动点迭代及图论算法完成对语义逻辑的审视，复刻了经典 Chomsky 层级定义。外围配套多平台 JSON 输出与 BFS 有界广搜推演反证。系统实现高度切合专业计算机实验报告所需的学术严谨性、数学验证准确性以及鲁棒的工程落地标准。
